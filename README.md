# 文学指纹 · Literature Fingerprinting

> 不用写代码，也能一眼看懂「不同作家的写作风格差在哪里」。

## 📖 产品介绍

### 这是什么？

「文学指纹」（Literature Fingerprinting）是 Keim & Oelke (2007) 提出的一种方法：把一部小说切成一段一段，计算每一段的平均句长、词汇丰富度等特征，再把这些特征画成像素块和交互图表。每个作家写作的习惯不同，画出来的「指纹」也就不一样——于是你就能直观地看到他们风格的差异。

本项目把它做成了一个开箱即用的网页工具：基于 Python 计算 + D3.js 交互图表，全程可视化操作。

### 能做什么？

- **分析自己的书**：上传任意一部英文小说（`.txt`），几秒钟生成它的「文学指纹」。
- **和名著对比**：与内置的 4 本示例名著（马克·吐温、杰克·伦敦各两本）并列对比。
- **层层下钻**：拖拽、点击、悬停，一路深入到具体段落，看这本书的高潮在哪、哪段最特别。
- **留存自己的分析**：勾选「存入我的图书馆」，上传的派生指纹会保存为 `data/library/*.json`，刷新后仍在，可随时用书名旁的 ✕ 删除（内置示例书不可删，重名会自动改名、不会覆盖）。
- **出处定位与复制**：每个数据点都标注「第 X/N 块 · 约全书 Y% · 本块词数」，可一键复制原文片段用于写作引用。
- **带范围的解读**：指标提示给出按当前已加载书籍算出的参考区间（随数据变化），Honoré 等指标附「宜同尺度横比」的提醒，避免把裸数字当绝对标准。

### 适合谁？

文学研究者、语言学习者、读书爱好者，以及任何想「用数据看文学」的人——**全程不需要写任何代码**。

## 🚀 基本使用步骤

1. **启动**：双击 `start.bat`。
2. **等待**：脚本会自动准备示例数据（首次运行约 1-2 分钟），然后自动打开浏览器。若页面还没加载出来，稍等几秒刷新一次。
3. **看示例**：页面顶部已内置 4 本名著，直接点击书名即可查看它们的指纹。
4. **分析自己的书**：点顶部的「上传文本分析」，选一个英文 `.txt` 文件，几秒后它就会出现在书名列表里，和示例书并列对比。想留档就在「上传」旁勾选「存入我的图书馆」（本地版默认勾选，在线演示默认不勾）——之后刷新页面它仍在。

## 👀 怎么看这些图

1. **选书**：顶部点书名（可一次点多本），图表会自动变成多本书并排对比。
2. **看局部**：在右下角「趋势演变」图上按住鼠标左键左右拖拽，选出一段（比如某个章节），左边所有图会立刻只显示这一段的数据。
3. **看细节**：点任意柱子或线条，右侧会弹出这本书在这一段里数值最高的 3 个段落，附原文片段和关键词。
4. **排序与高亮**：点图表标题旁的排序图标可切换排序；鼠标悬停任一元素，相关的书会被高亮、其余自动变暗。

## 📊 这些指标是什么意思

- **平均句长（Average Sentence Length）**：一句话平均多少个单词，数值越大句子越长、越书面。
- **辛普森指数（Simpson's Index）**：词汇丰富度，越接近 0 用词越丰富，越接近 1 越重复。
- **Honoré 词汇丰富度 R（字段名仍为 Hapax Legomena）**：由词元总数 N、不同词型数 V 和只出现一次的词型数 V1 综合计算，当前实现公式为 `R = 100 × ln(N) / (1 - V1/V)`。它通常不是 0–1 的比例；数值越高，一般表示词汇使用越丰富。
- **功能词 PCA（Function Words PCA）**：看「的 / 和 / 是」这类高频小词的使用习惯，反映语法风格。

## ⚠️ 注意事项

- **只支持英文文本**：目前算法按英文设计，中文等其他语言的结果不可靠。
- **文件格式**：请用 `.txt` 纯文本，UTF-8 编码。
- **文本长度**：正文至少约 1 万词，建议几万字——书越长，趋势图越丰富；太短会无法生成指纹。
- **首次运行较慢**：第一次启动要生成示例数据，约 1-2 分钟，之后秒开。
- **页面打不开**：若浏览器没自动打开或页面空白，稍等几秒刷新；若仍不行，可能是 5000 端口被占用，关闭占用程序后重试。
- **隐私与留存**：上传属于即时分析。只有勾选「存入我的图书馆」后，派生指标与片段预览（长片段预览可大段覆盖原文）才会写入当前服务器的 `data/library/`：本地版默认勾选（本机留档），在线演示默认不勾（不落盘，重新部署还会清空）。内置示例书永不会被覆盖或删除。当前在线演示使用 HTTP，不应视为加密传输，请勿上传敏感、私密或未获授权的文本。

### 本地开发

环境要求：Python 3.10+（开发与测试环境为 Python 3.13）。

```bash
# 1. 克隆项目
git clone [repository_url]
cd Literature-Fingerprinting

# 2. 安装依赖
pip install -r requirements.txt

# 3. (可选) NLTK 数据包会自动下载，如遇网络问题可手动运行：
# python -c "import nltk; nltk.download('punkt'); nltk.download('stopwords')"
```

**手动启动**：预生成示例数据（服务器在首次请求时也会自动生成）：

```bash
python generate_data.py
```

再启动 API 服务器，然后访问 <http://localhost:5000/visualization>：

```bash
python api_server.py
```

**运行测试**（指标 + 书库 API 全套）：

```bash
python -m unittest discover -s tests -v
```

**删除「我的图书馆」里的书**：删除需要保存时签发的令牌（存在保存它的浏览器里），
本机也一样——`Host` 头是客户端说了算的，拿它当删除授权等于没授权。
清过浏览器数据、又想删掉本机的旧文件时，可以显式开启本机豁免：

```bash
# Windows (cmd)
set ALLOW_LOCAL_DELETE=1 && python api_server.py
# macOS / Linux / Git Bash
ALLOW_LOCAL_DELETE=1 python api_server.py
```

或者直接删掉 `data/library/<书名>.json`。

**Streamlit 经典模式**（⚠️ 已归档，仅作实验性参考；正式产品为上方 D3 版，新用户无需关注）：

```bash
streamlit run app.py
```

## 🔧 变更记录：界面文案纠错与两个渲染缺陷（2026-09-27）

这一批只做「说错的话」和「会坏的地方」两件事，不动配色、不动算法、不动任何指标口径。

**说错的话。** 界面在四个地方告诉用户风格星系的坐标是按中文虚词「的、和、是」算的，
但语料是英文小说，真实模型用的是 `the / his / of / he`（横轴）与 `and / he / you / that`
（纵轴），而且同一页下方的图注早就在显示这组真实的英文词——页面自己打自己。
现在轴词例子改为从后端 `projection.axisLabels` 实时取用，取不到时只说「高频小词」、
不编例子。另一个错误是「独特词丰富度」被描述成「占比」：它实际是
`R = 100 × ln(N) / (1 − V1/V)`（本书 52 行的写法才是对的），实测区间 1725–2516，
按「占比」去读会差一个数量级，三处文案已按 52 行的口径改写。
另外还修了「区域平均平均句长」的叠字、什么都说明不了的图例「一端 / 另一端」、
以及风格星系面板里书名显示成截断英文（`The Call of the …`）而别处显示《野性的呼唤》的不一致，
CSV 第一列的书名也一并统一成中文名。

**会坏的地方。** 风格星系在缺高频小词数据时引用了一个从未声明的变量，抛出异常后
画布已经清空却没有任何说明，还会把一次成功的上传误报成「上传失败」；
折线图不会清除上一次热力图留下的行内高度，书少时（含默认的单本）图会缩在一片空白中间、
导出的 PNG 也跟着大半张空白；首次加载慢时先完成的上传会被后到的整份数据覆盖掉；
全书对比页的导出按钮写死了「整体水平对比」，导致「风格走势」那张永远导不出来。
四条都已修复。顺带删掉了页面上一个从未被写入过的空图例盒子（`#legend` 及其 CSS）
和一个无人调用的 `toggleMetric()`。

**上面 53 行那条例句（「的 / 和 / 是」）与本批修的是同一个错误，但按「README 只追加」
的约定，那行原文保留不动，仅在此说明。**

## 🔧 变更记录：绘图边界的五处越界与手机端三处遮挡（2026-09-27）

承接上一批，这一批只修「画出来的东西是错的」和「小屏上点不到」，同样不动算法与任何指标口径。

**坐标轴上下界。** 折线图用乘法给纵轴留白（`extent[0] * 0.95`、`extent[1] * 1.05`），
乘法对负区间方向是反的：区间全负时下界反而被抬高、上界被压低，可视窗口比数据本身还窄。
「风格走向」的横坐标是 PCA 有符号值，内置书里本来就是负数（实测 −0.0597 ~ −0.0169），
于是 102 个片段里有 12 个被画到横轴下方、最高的那个点顶进图标题。改为按本跨度做加法 padding，
正负区间都是往外撑，实测越界点数由 13 降到 0。

**热力图画布高度。** 每本书的格子边长按它自己的 `cols` 各算各的，旧代码却拿第一本的格子边长
去乘全局最大行数。只要后面某本书的格子比第一本大，它的网格就会伸进下边距，
图例条和「虚线是章节分界」那行说明正好压在最后一排格子上。改为逐本算出 `rows × blockSize`
再取最大值，两本书的对照用例下网格底 336、图例 438、章节注 470，重叠消除。

**导出。** 导出的 SVG 里原本没有 `.zero-line` / `.annotation-point` / `.selection` 规则，
读者拿到的图会丢掉零线、标注点和框选框；两张图各自内联一份样式表也容易漂移，
现在合并为单一常量。同时补上了导出图例：仪表盘导出的图会带书名色块，星系导出会带
图例和轴说明，星系那张的轴说明实测按 2 行折行。热力图配色另有一处对比度问题——
图例上「低 · 短句」的墨色直接用了色阶端点（#7f9dc4，对比度 2.66:1，低于 AA），
改为深色墨（实测 rgb(44,74,110) / rgb(143,29,22)）。

**手机端遮挡。** 提示框用绝对定位贴在光标右下，靠近右边缘时被浏览器压成 73px 宽的竖条
（实测旧行为），现改为 `position: fixed` 并按视口宽高钳制，真 390px 视口下实测 206×123、
右边界 382 未溢出。「停止文本雨」浮动按钮固定在右上角，在 320px 宽度下正好压住吸顶的
页签栏——实测两者重叠 1777px²，且页签中心的 `elementFromPoint` 命中的是按钮而非页签，
点「风格星系」会误触发文本雨；现移到右下角，重叠归零、命中回到页签本身。

**框选范围说清楚。** 在「风格走势」上框选后，卡片标题、解读、提示框都只统计框选区段，
但文案没有任何说明，读者会把它当成全书水平。现在标题带出「（框选区段 0.0%–30.0%）」，
解读首行说明「只统计框选区段，不是全书」，而异常对比那句仍然按全书平均比，
并显式标注「不受上方框选影响」。

以上全部为工作区未提交状态；`src/` 与 `api_server.py` 一行未动，`python -m unittest discover -s tests`
仍为 147 项全过。

## 🔧 变更记录：数值口径统一、离线可用与一处自相矛盾（2026-09-27，第二批）

**悬停提示框印原始浮点数。** 同一文件里那句「四个出口（详情面板 / 图注 / 摘要 / 悬停）口径一致」
是实现者的原意，但悬停这个出口写的是 `escapeHtml(data.value)`，直接把 JSON 里的原值印出来：
「风格走向」的一个片段悬停显示 `-0.019992956022007756`（21 位），点开详情却是 `-0.020`。
四本内置书的四个指标全都如此（`25.1692` vs `25.17`、`0.011755` vs `0.0118`、`2075.0013` vs `2075`）。
现改为统一走 `formatMetric`；顺带把风格星系的调用点从「先格式化再传字符串」改成传原始数值，
否则字符串会命中 `formatMetric` 的 `!isFiniteNumber` 分支、四个出口里三个显示「暂无」。

**d3 改为本地副本 + CDN 兜底。** 整页的图表与全部交互都建在 d3 上，而它一直从 `d3js.org` 取；
那个域名取不到就是整页不出图、页签也切不动。现在仓库里带一份 `static/js/vendor/d3.v7.min.js`（v7.9.0），
优先走本地、不发网络请求；万一本地副本缺失，下一行会在 `window.d3` 为空时补一份 CDN 的
（实测：临时移走本地副本后 `d3js.org` 那份被拉起来，`d3.version` 仍是 7.9.0）。
图标字体仍是 CDN——只有 8 个装饰性图标，取不到时 `<i>` 渲染成空元素，不影响功能。

**全书对比页的提示框被挤成竖条。** 这个页签的提示框是另一个元素（`#adv-tooltip`），样式全写在 JS 里，
只写了 `left: pageX+10`。绝对定位元素的宽度由「容器剩余宽度」决定，320px 下悬停走势图最右那个点，
可用宽度只剩 44px，提示框被压成 **47×140** 的窄竖条（一次只显示一个字），还把页面撑出横向滚动条。

## 🔧 变更记录：风格星系的轴说明说反了一半（2026-09-27，第四批）

**问题**：风格星系图下面那两行轴说明，横轴是对的，纵轴四个词里有两个说反。

`src/projection.py` 的 `axis_labels()` 按每个主成分**载荷的绝对值**取前四个词，再套一句
「越靠右／上，这些词占比越高」。但载荷是**带符号**的：正负代表坐标轴上相反的两端。
一句话只能管一个方向，把两种符号混进同一句，混进来的那一半无论比例尺朝哪边都必然说反。

实测 `pca_model.json`：

| 轴 | 取到的前四词（载荷） | 结果 |
|---|---|---|
| 横轴 PC1 | the +0.556 ／ his +0.340 ／ of +0.298 ／ he +0.280 | 全是正号，**原本就对** |
| 纵轴 PC2 | and +0.770 ／ he +0.263 ／ **you −0.217** ／ **that −0.177** | 混进两个负号，**and 和 he 说反** |

还有第二处错：`static/js/d3-charts.js` 里星系的 `yScale.range([padding, height - padding])`
把数值大的一端放在**下方**（SVG 的 y 向下增大），文案写的却是「纵轴越靠**上**」。
两处错部分互相抵消，最后表现成「四个词里两个对、两个错」。

值得记一笔：**星系根本没画坐标轴，也没有刻度**（`axisLeft` 只在折线图里出现），
所以这两行字是全图唯一告诉用户「上／下是哪个方向」的东西，说错了没有别处能纠正。

**试过但否掉的改法**：把星系的 y 比例尺翻过来，与折线图同向。实测翻完之后**仍然是四个词错两个**，
只是错的那半从 and／he 换成了 you／that——翻朝向只能决定「哪一半错」，消不掉错误。
代价却是把星系整体上下镜像：此前导出的每张 PNG、分享出去的每张截图都不作数了。
而 PCA 主成分的正负号本来就是任意的，坐标轴并没有「值大＝更多」的语义，
为一个无含义的方向付这个代价不划算。

**实际改法**：`axis_labels()` 改成按载荷**符号分组**，一段只说同号的词：

- 横轴越靠右，the / his / of / he 这类小词在整段里占的比例越高　←　逐字未变
- 纵轴越靠下，and / he 这类小词在整段里占的比例越高；纵轴越靠上，you / that 这类小词在整段里占的比例越高

- `getAxisWordsFor()` 取轴词的正则原来没有 `g`、词表字符类也没排除分号，只看得到第一段；

- 导出图里轴说明的折行原来**两处各写各的**：算高度用 `Math.ceil(len/46)`，画文字用 `i += 46`
  且硬顶 4 行——说明超过 4 行、或长度不是 46 的整数倍时两者就对不上，图例带会盖住图或多出一截空白。

### 1. 解读里的「参照」和它左边的数字不是同一个口径（说假话）

框选生效时，解读面板会先声明「下面这些数字只统计走势图上框选的 X%–Y% 区段，不是全书」。
但紧跟其后的参照句，是拿**其它书的全书平均**去减**本书的区段平均**，再把差值说成
「这本书比它们低于约 X」——一本的区段数减另一批书的全书数，差没有含义。

实测（哈克贝利·费恩，用词重复度，框选 20.0%–50.0%）：

| | 数值 | 后果 |
|---|---|---|
| 本书·框选区段平均 | 0.0106 | — |
| 参照·其它 3 本**全书**平均（旧） | 0.0118 | 报「低于约 0.0012」 |
| 参照·其它 3 本**同区段**平均（新） | 0.0123 | 报「低于约 0.0017」 |

差被少报了约四成。新增的 `bookSegmentValues()` 用与 `initAdvancedData` 完全相同的口径
（`xPercent = i / (片段数 − 1)`、剔掉非有限值、套同一个区间）给其它书取数，参照句也写明
「在框选的 20.0%–50.0% 区段内平均约为 …」。顺带修掉一处小的：旧代码没剔非有限值，
而 `initAdvancedData` 剔过，所以参照数和走势图上画出的线本来就不是同一批数。

### 2. 取消勾选一本书之后，整页停在 12% 不透明度（会坏）

`advState.selectedIds`（哪些书的详情卡展开着）和 `selectedBooks`（图上有哪些书）是两份状态。
用户取消勾选一本书时只动后者，前者会留着一个图上已经不存在的 id，于是
`updateHighlightVisuals()` 把**每一本**都调暗、再去点亮那本已经不存在的书——
一本都没亮，整页发灰；详情卡也还挂着一本不在图里的书。

同一状态下新旧逻辑的实测对照（`.book-el` 共 3 个）：

| | 调暗数 | 点亮数 |
|---|---|---|
| 旧逻辑（不过滤） | **3** | 0 |
| 新逻辑（过滤后） | **0** | 0 |

新逻辑把过滤后为空的选择当作「没选」，整页恢复常态、详情卡回到空提示。
用**过滤**而不是从 `selectedIds` 里删，所以重新勾选这本书时详情卡会自动回来（已实测）。

- 重画清单加上 `updateDrillPanel()`；
- `advMeanLabel()` 带上指标名 → 「平均句长」「区段平均句长（20.0%–50.0%）」。

### 5. 横轴写着「阅读进度」，可它不是进度（说假话）

主视图折线图的 `xScale` 定义域是 `[0, maxBlocks]`，每本书按**自己的**片段序号画
（`.x((d, i) => xScale(i))`），而各书片段总数差 4.6 倍（野性的呼唤 22 个、哈克贝利·费恩 102 个）。

这里也没有做任何归一化，所以连「百分比」都不能叫。原来那句
「阅读进度（每个片段约 1 万个单词）」会让人把两条线在同一个 x 上直接对比，读出不存在的结论。
改成两行：

```
片段序号（每个片段约 1 万个单词）
各书片段总数不同，同一个序号不代表相同的阅读位置
```

（看板页的走势图才是归一化到 0–100% 的，那里「阅读进度」的说法保持不变。）

## 🔧 变更记录：同名的三种结局、看板的键盘通路与四处口径（2026-09-27，第六批）

> **先更正本文档自己的一句话。** 上文「能做什么？」一节写着「重名会自动改名、不会覆盖」。
> 这句与服务端 `_resolve_final_name()` 的行为**正好相反**：书库里已有同名时它沿用的是同名、
> **原地替换**，上一版分析就此消失。按「README 只追加、不改旧行」的约定，那句保留在原处，
> 特此作废，以本节为准。（页面上那条一模一样的 tooltip 已按实情改写。）

### 1. 同名的三种结局，以前一种都不说

同一个文件名，落到磁盘上有三种完全不同的结果，而界面上给的是同一句「分析完成」：

| 情况 | 服务端做的事 | 用户以为的 |
| --- | --- | --- |
| 撞上内置示例书名 | 另存为《X（我的）》，示例书不动 | 我传的这本进去了吗？ |
| 撞上书库里已有的同名书 | **整份替换**，上一版分析消失 | 我在「新增」一本 |
| 没勾选保存、但书名重名 | 磁盘上留着的还是旧的那本 | 书库里那本已经更新了 |

现在响应里带 `renamedFrom` / `replacedExisting` / `shadowsExisting` 三个字段，
`handleFileUpload()` 按情况把话说在完成提示后面。CDP 走 `<input type=file>` 的真实文件选择
路径实测四条，逐字如下（每条分析 2.7–3.1 秒）：

1. 全新名字 + 勾选 →「『lit6-重名测试』分析完成，共划分 23 个片段。已存入「我的图书馆」，刷新后仍在，可点书名旁 ✕ 删除。」（无附加句）
2. 同名再传一次 →「…**书库里同名的《lit6-重名测试》已被这次的结果整份替换，上一版分析不再保留。**」
3. `White Fang.txt`（撞内置《白牙》）→「…**《白牙》是内置示例书的书名，这次存为《White Fang（我的）》，示例书不受影响。**」
4. 取消勾选后再传同名 →「…本次未勾选保存，刷新后不会保留。**书名和你已保存的《lit6-重名测试》重名：屏幕上显示的是这次的分析结果，书库里存着的仍是上次保存的那一份（这次未勾选保存）。**」

勾选框的 tooltip（`d3_visualization.html`）随之照实重写，`_resolve_final_name()` 的 docstring
也补上了「注意 1) 是**会毁掉旧数据的**」。

### 2. 落盘失败不再连分析结果一起丢

「我的图书馆」写入失败时，原来直接返回 500 且不带 `data`，前端据此提前 return，
文案却说「请改在上方展示区查看」——指向一个根本不会出现的书名；用户唯一能做的就是重传一遍，
而磁盘问题没解决必然再失败一次。高成本的那一步（几秒的全书分析）已经跑完了，不该丢掉：
现在照样下发结果（`saved=false` + `warning`），图上能正常看，只是刷新后不留存。

### 3. 单次分析的片段数有了上限（600）

50 MB 只是「文件字节」这道闸门，换成英文正文能装下几百万词，而分析开销随片段数线性增长。
上限拦在 `build_book_data()` **之前**（拦在后面正是要避免的那段等待），报错说清三件事：

> 文本太长，单次最多分析约 600 个片段（覆盖约 60 万英文单词），这份文本约 848 个片段。请拆分文件后分次上传，或先截取要研究的那些章节。

（「覆盖约 60 万词」按 `(600-1) × (10000-9000) + 10000 = 609000` 算，不是「片段数 × 1 万」——
片段之间重叠 9 千词。）

### 4. 把摘录当全文说

一个片段约 1 万个英文单词，弹窗里给的始终是开头的 1200 字，而那一节的标题叫
**「原文深度阅读」**、按钮叫**「复制全文」**。把摘录当全文引用出去，是读者看不出、作者会吃亏的
那种错。现在标题是「📜 原文片段」、按钮是「⧉ 复制这段摘录」，正文上方多一行 `#modal-text-note`：

> 本片段共约 10,000 个英文单词，此处显示开头 1200 个字符（约占 2%），不是全文。

字数按**真正显示出来的**字符算（`_preview()` 补的三个点不算原文），所以老数据只带 150 字摘录时
不会写成 1200。卡片里那个「复制片段」同理改成「复制摘录（1200 字）」，并加一句 `.excerpt-note`
说明引文比复制到的短。

### 5. 四个指标的摘录长度本来不一致（后端）

`build_book_data()` 里只有 `functionWords` 带了 `extended_preview`（1200 字），
另外三个只有 `preview`（150 字）。于是**同一个片段，只换一下「观察角度」**，弹窗里的原文就从
1200 字缩成 150 字——而标题和按钮都自称全文。现在四个指标统一走 `_block_entry()`，
`CARD_PREVIEW_CHARS = 150`、`MODAL_PREVIEW_CHARS = 1200`。

### 6. 看板页的钻取与框选只能鼠标

「哪一段偏离得厉害」正是从片段详情卡里读出来的，而柱子和折线都是不可聚焦的元素，
键盘用户在看板页打不开任何一本书的详情；框选（区段平均的唯一入口）更是 d3.brush 的纯鼠标操作。

- `attachDrillKeyboard(nodes)`：整张图只留**一个** Tab 停靠点，进去之后方向键逐本走、
  Home/End 到两端、Enter/Space 展开，`role="button"` + 带书名/指标/数值的 `aria-label`。
  走法沿用图上别处已经做好的那套，避免几十根柱子各占一个 Tab。
- `attachBrushKeyboard(g, brush, w)`：方向键平移整个框（每次 1% 宽）、Shift + 方向键收放右边界、
  Esc 清空；还没框过时第一次按键先划出中间一段，用户不用凭空知道该按哪边。
- 顺带修掉一个**上一批自己引入的错误**：`bars` / `paths` 是 `.data()` 的 **update 选择集**
  （首屏渲染时它是空的），键盘必须挂在 `.join()` 返回的合并集上；挂在 update 集上等于
  首屏一根柱子都点不到。鼠标能点是碰巧——`.on()` 链在 `join()` 的返回值上。实测修复后
  4 根柱子、4 条折线都带 roving `tabindex` 与 `role="button"`。

### 7. 「✕ 收起」之后焦点掉回 body

被点掉的那个按钮正是刚被重建掉的节点，键盘用户按一次回车就迷路了。现在把焦点接到
`#adv-drill-content`（带 `tabindex="-1"`，再往下 Tab 一次就回到还没收起的卡片按钮上）。
这一块同时补了播报：它以前**不出声**（同屏的 `#insight-content` / `#anomaly-content` 都带
`aria-live`），但整块做成 live region 会把卡片里的按钮和关键词一起念好几遍，
所以内容区只当普通区域（`role="region"` + `aria-label`），另设视觉隐藏的 `#adv-drill-announce`
（`role="status"`）播一句话：

> 已展开 2 本书的片段详情：《哈克贝利·费恩历险记》、《野性的呼唤》，每本列出数值最高的 3 个片段。

`updateDrillPanel()` 也顺手改了写法：原来是每本书一次 `panel.innerHTML +=`，有几本书就整块
重建几次——屏幕上闪，live region 也跟着报几遍；现在是拼好一次写入。

### 8. 系统里关了「减少动态效果」，页面照样满屏飞

`prefersReducedMotion()` 以前只用来决定文本雨的默认开关，而页面里真正会动的东西——d3 的全部过渡、
风格星系每次进入那场约 5 秒的力导向收敛——一条都没走这个判断。新增 `motionDuration(ms)`
并接入所有 d3 过渡（`d3_visualization.html` 里那个脚本用 `animMs()` 转发，免得到处写 `typeof`）。
压成 **0 而不是「不动」**：不动的话柱状图会停在上一次的旧高度上。星系则在
`prefersReducedMotion()` 时先在内存里 `tick(120)` 再一次性画出来——`tick()` 不触发 `"tick"` 事件，
所以算完必须手动调一次 `ticked()`，否则屏幕上是一片空白。

### 9. 星系每次进入都从零重跑力导向

切页签、换指标、换书、拖窗都要重看一遍那场约 5 秒的抖动，用户手动拖开的那几个点还会被拉回原位。
现在 `galaxyPositions` 记下落点，下次进入从上次的稳态接着算（`alpha(0.35)`、`alphaDecay(0.06)`，
不再从 `alpha=1` 退火）；只在落点仍落在这一屏里时才用——换了几本书坐标尺会整个变，
旧点位跑到屏外反而要花更久才被拉回来。「↻ 重新布局」按钮先 `galaxyPositions.clear()`，
它「真的重新排一次」的承诺因此不受影响。实测：清缓存重进，第一个点位与上次记录的坐标
逐位相同（0.0px）；普通重进则相差 4.4px（力导向确实接着算了，而不是原样复读）。

### 10. 320px 下热力图图例的「低 · 」被裁在画布外

色带宽度写死 220，两个标签又各贴着色带往外排 10px：在 320px 宽的屏幕上左端只剩「短句」，
「低 · 」整个落在画布外，读者只看到右端有「高」，左端是什么就没了对照；换成「独特词丰富度」

### 11. 导出的条形图丢了口径说明

### 12. 触屏上教用户「滚轮缩放」

手指没有滚轮，也没有「悬停」。两句提示都写在 HTML 里，由 CSS 按 `@media (hover: none)` 择一显示

## 👆 变更记录：手指上的可点面积、摘录口径与最后一处外链（2026-09-27，第七批）

上一批末尾那份「没做的」清单，这一批逐条清掉；同时把其中两条**先量了一遍**，
发现有一条已经不成立、另一条的数字要改口——都写在下面。

### 1. 触摸目标：17 个小于 44×44 → 控件 0 个

320×760、开触摸模拟实测，页面上有 17 个可点元素小于 44×44。现在用一个 `@media (pointer: coarse)`
把它们撑起来：页签、快速开始、导出按钮、书名 chip、筛选芯片、排序控件、复制按钮、「存入我的图书馆」、
下拉框给 `min-height: 44px`；弹窗右上角的 `×` 给足 44×44；书名旁的删除钮只撑**命中区**（见下）。

为什么用 `pointer: coarse` 而不是 `max-width`：这里要表达的是「输入是手指」而不是「屏幕窄」。
平板横屏不窄，带触摸屏的笔记本主指针却是触控板（`pointer: fine`）——按宽度写，这两种情况都会判错。
放在样式表最后，是为了压过上面那些按宽度写的移动端微调（例如 ≤560px 里把 `.cyber-btn-float`
压成 `padding:5px 11px` 的那条），否则同一条属性谁在后面谁赢。

**「停止文本雨」93×28 与「上传文本分析」154×42 是第一次漏掉的**：前一版只按「按钮」这个直觉挑选择器，
漏了这两个类名不同的（`.cyber-btn-float`、`.upload-btn`）。复量时才发现，一并补上。

**删除钮的命中区**：`.book-del` 实测 38×22。它做的是删除，改小不行、改大会盖住旁边的书名 chip
（变成「想选这本却删了那本」），所以只撑竖向、横向不动，用 `::before` 撑到 44px——正好是
`.book-group` 的高度，一格不越界。这里有个坑：**定位伪元素的参照物是 padding box，而 `.book-del`
有 1px 的透明边框**，所以 `top/bottom` 给 −11px 只能得到 42px，必须给 −12。
（`getBoundingClientRect()` 量不到伪元素，验证得用 `elementFromPoint` 打车上下边缘的点；
上一版我据此以为「向下没撑到」，其实是探针正好打在半开区间的边界那一像素上。）

### 2. 摘录字数：两处一个算法

同一段摘录，卡片按钮写「复制摘录（1200 字）」、弹窗按钮写「复制这段摘录（1203 字符）」。
差 3 是因为卡片按 `_preview()` 补的省略号扣掉再数、弹窗按原始长度数；「字」与「字符」混用是因为
正文是英文，说「字」本来就不准。现在统一成 `excerptCharCount()`：**只数真正复制到的正文字符**
（省略号是界面加的，不是原文），单位一律「字符」，两处都从这一个函数取。

### 3. `clean_text()` 的贪婪正则：单行输入会把正文清光

原来起始标记用 `.*`（贪婪、默认不跨行），只会在**同一行里**一路吃到最后一个 `***`。
正常的多行文本两种写法结果相同；但 `START` 与 `END` 落在同一行时（复制粘贴丢了换行、
或整本书被拼成一行），`start_match.end()` 会跑到 `end_match.start()` 之后，切片变成空串——
整本书的正文被清光，用户只看到「清洗后没有剩余正文」，完全看不出是自己那份文件的换行没了。

改成非贪婪 `.*?`，并补一道 `start_match.end() < end_match.start()` 的顺序保险（两个位置万一颠倒，
宁可不切：少剥一层页眉只是数值略有偏差，切光了是什么都没有）。同时收下老版标记的
`THIS PROJECT GUTENBERG` 写法——原来只认 `THE`，这类文件的页眉页脚会整段留在正文里，
而界面与导出都写着「文本经页眉页脚清理」，那句话就成了假话。

**四本内置书的清洗结果逐个对过 sha256，字节级不变**（568322… / 390259… / 175204… / 396310…），
即老语料的行为严格没变；退化用例新增 3 个测试（单行标记、`THIS` 标记、标记顺序颠倒）。

### 4. 最后一处 CDN：图标字体随仓库带

`font-awesome` 6.0.0 仍在从 CDN 引：离线或校园内网打开时，8 个图标一个都不显示。d3 从第三批起
已经是仓库内的本地副本，留这一个外链等于整站还是「联不上网就掉东西」。现在同版本随仓库带一份
（`static/vendor/fontawesome/`，`all.min.css` + 4 个 `woff2`，共 352K；`.ttf` 是老浏览器的后备，
没带，现代浏览器都用 woff2）。

### 5. 术语与标点

导出摘要里写「共分析 N 本书、M 个**文本块**」，而界面上另外 110 处一律叫「片段」（「第 3 个片段」
「切成 102 个片段」「参与统计的片段数」）——同一份导出里两种叫法。统一成「片段」，
紧接着那句「按每块 10000 词、相邻块重叠 9000 词」也一并改口。
全文扫过一遍半角/全角括号、逗号、冒号混用，没有发现真问题（命中的都是 HTML 属性引号）。

### 6. 配色与对比度：实测下来这一条**已经不用做了**

上一批把「配色/对比度」列成了待办，这一批先量再动手。写了个审计脚本走遍三个页签的
每一个文字节点，把祖先链上的半透明底色逐层叠到纸底色上再算对比度（**这一步很关键**：
直接拿 `getComputedStyle().backgroundColor` 的原始色去比，会把 `rgba(107,143,90,0.10)`
当成一片深绿，报出「白字压在绿上只有 1.63:1」这种假警报——我第一版就是这么误报了两处，
合成之后归零）。

结果：**三个页签、0 处文字对比度不合格**。热力图色阶在更早的批次里已经按你选的
「保持蓝红、只拉明暗」调过（两端亮度拉到 3.19:1，代码注释里记着当时为什么这么定），本轮没动。

**验证**：`node --check` 两个脚本通过；`python -m unittest discover -s tests` **151 项全过**
（148 + 新增 3；本批不动任何指标算法）；320×760 触摸模拟下用 `elementFromPoint` 复核了
删除钮命中区（上下各 21–22px 均命中）、`min-height` 之后的控件尺寸、三个页签的渲染
（热力图 102 格 / 星系 102 个点 / 看板 3 个 chip）；导出摘要实测输出

## 🔧 变更记录：同一本书终于同一个颜色、切页签滚到内容（2026-09-28，第八批）

这一批的五项有一个共同点：**都不会让程序崩，但都会让读者读错图或看不懂图**——而这正是
这个工具的目标用户（不做统计、不写代码的文学研究者）最扛不住的失败方式。第七批修的是
「说错的话」，这一批修的是「同一件事在不同页签说得不一样」和「图上一件事根本没人说」。

### 1. 一本书在三个页签里是三种颜色（本批最重要）

折线图、风格星系、看板各自建了一个 `d3.scaleOrdinal()`，**颜色表完全相同（同样 8 个色值），
但 domain 不同**：折线图与星系用「当前选中顺序」，看板用「全库顺序」。结果同一本书换个页签
就换个颜色。实测：《白牙》在星系是 `rgb(79,122,140)`，在看板是 `#a67c3d`。

阅读时颜色就是「这是哪本书」的唯一线索，一本书两个颜色等于两本书，图例跟着一起乱。

改法是新增 `colorForBook(name)`：domain 统一建在 `Object.keys(realData)`（**看板本来就在用的
那个顺序**），折线图与星系向看板看齐。这么选是因为 d3 的 ordinal 取色就是
`range[domainIndex % range.length]`，按下标算与旧行为**逐位等价**——所以看板上的配色一位都
不变，用户看到的颜色只朝「同一本书终于一致」这一个方向变。查不到书时退回确定性字符串哈希
（不引入 `Math.random()`，那条分支实际不可达，是纯防御）。

顺带清掉一处死代码：星系建渐变的循环遍历的是 `books`（图例用，含未画入的书），而圆点只来自
`plotBooks`——被跳过的书会生成一批没有任何地方引用的 `<radialGradient>`。改成遍历 `plotBooks`。

### 2. 热力图下不再藏掉「可以多选对比」那句话

原逻辑在切到热力图时把 `#toggleComparison` 一并藏了，理由写在注释里：「热力图不支持多书
对比」。**这条注释是错的**：`drawMultiHeatmap` 就是按书循环、一本书一列画的（实测选 2 本画出
85 格）。所以被藏掉的不是入口（那本来就只是一句提示语，没有点击处理器），而是**一句在热力图
下仍然为真的话**。现在只保留「曲线平滑」那一组的显隐——那个是真的没有曲线可平滑。

### 3. 「大小 = 数值高低」没说清是哪个指标

星系的位置**恒定**取「风格走向」的二维坐标，只有圆点大小跟「观察角度」下拉走。而图例那行
只写了「大小 = 数值高低」，读者无从知道是哪个指标的数值高低。现在它会写出当前指标的
名字（`大小 = 「平均句长」的数值高低`）。

**一处必须特判**：当指标恰好是「风格走向」时，横向位置用的 `pcaX` 与大小用的 `value`
**是同一个数**（后端把 PCA 第一主成分同时放进了这两个字段）。写「数值高低」会暗示这是两套
独立的编码。这种情况改写为「（与横向位置同源）」。

这句也一起进了导出的 PNG/矢量图——图会被放进论文，光看图的人更需要知道大小是什么。

### 4. 点云为什么只占画布三成宽，页面从头到尾没说

实测：1440 与 900 两种宽度下，点云的横向填充都只有 30–31%，质心明显偏左。原因是**有意的
设计**——可比时所有书共用内置示例书的固定轴范围，只选一两本时点自然聚在中间。但页面上没有
一个字解释过，读者的第一反应是「图坏了」或者「这几本书特别像」。

现在在星系说明面板里加了一句中性的补充说明。它只在**坐标可比且没有越界**时出现，写在原来的
`else` 分支内部，所以「各书各自计算」（范围不共享）、混用旧数据、没有可比书这三种情况会自动
排除，不会和面板上已有的 ⚠ 告警打架。

### 5. 切页签之后滚到内容

页签条以上压着约 630px 的标题/选书/上传/指标/快速开始/工具条，之前切页签是不滚的：
点完「风格星系」，屏幕还停在选书那一屏，得自己往下拨。现在切完页签会把该视图的顶部滚到
吸顶条下沿。

几个必须自己处理的细节：

- **吸顶条高度不是常量**（窄屏改过字号内边距，`flex-wrap` 换行后更高），所以每次实测再算 Y，
  而不是在 CSS 里写一个必然在某些宽度下遮住标题的 `scroll-margin-top`。
- **减动效的用户必须由 JS 自己问**：`window.scrollTo` 显式传入的 `behavior` 会覆盖 CSS，
  CSS 里那条 `scroll-behavior: auto !important` 保护不了这条路。
- **从分享链接进来时不滚**：那一刻数据还没到、三个视图都是空盒，而且要和浏览器自己的滚动
  还原抢，所以深链恢复页签时显式关掉滚动（`{ scroll: false }`）。
- **键盘切换时 `focus()` 加 `preventScroll`**：否则平滑滚动还在途中，`focus()` 会把页面拽回
  页签条，两个偏移打架。

**已知代价（不是 bug）**：滚到内容意味着全局工具条（导出图像/矢量图/数据表/摘要/引用/复制
链接）和指标条会被推到屏幕上方，原来是「导出按钮一直看得见」，现在是「往上滚一下才看得见」。
两者不可兼得，选了「切完页签立刻看见图」。

### 6. 实测中查出来的一个真问题：滚多了 10px

按计划断言「视图顶部 >= 吸顶条下沿」时，实测差 2px（视图 55、吸顶条底 57）——标题压进了
吸顶条两像素。

原因是 `.view-section` 每次显示都会重跑一遍 `fadeIn` 动画，而它的 `from` 状态是
`translateY(10px)`。切页签的那一刻量 `getBoundingClientRect()`，量到的是**被动画挪下去
10px 的假位置**，照着它滚就多滚 10px，正好把留的那点缝（`+8`）吃干净还倒欠 2px。

改成用 `offsetTop` 逐级相加算布局位置（`layoutOffsetTop()`）——`offsetTop` 反映的是布局盒，
动画在跑也不受影响。修完实测：视图 66、吸顶条底 57，四种路径（鼠标点、键盘方向键、
减动效、切回基础页）全部一致。

**验证**：`node --check` 两个脚本通过；`python -m unittest discover -s tests` **151 项全过**
（本批不动 Python，数量与开工时一致）。实测用的是真浏览器（CDP）：三张图的取色改成
「同一本书对调选书顺序后逐条相同」（改前星系必错）；星系首个圆点的 `fill` 指向的渐变
仍能在 DOM 里找到（证明 defs 那次改动没删错）；热力图下提示语 `display:block`、高 46px，
折线图下平滑控件才出现；星系的「大小 = …」在切换指标时正确改写、而轴说明**逐字未变**
（位置不由指标驱动），导出说明实测 6 行、未触发截断（为此把折行上限从 6 提到 7）；
点云的三种合成入参各自走到正确的分支；小视口 1000×700 下四条滚动路径全部到位；
`?view=view-galaxy` 深链加载后 3 秒仍是 `scrollY === 0`；热力图仍是连续色阶
（102 格里 88 种不同颜色，没有被 8 色污染）、文字雨仍能打开。控制台错误只有既有的

## 🧹 变更记录：首屏减重、三处重复文案与看板片段详情自动就位（2026-09-28，第九批）

前八批一直在修「说错的话」和「说不一致的话」。这一批换方向，治两件用户每次打开都会碰到的事，
外加清掉三组「同一屏里说同一件事」的引导语。取舍标准只有一条：**不减少可发现性，只减少重复和噪音**——
每一项都要能回答「删掉之后，用户会不会因此不知道该干什么」。

### 1. 看板「片段详情」默认就是满的（本批最重要）

**问题**：左侧柱状图已经把每本书都画出来了，右侧「片段详情」却写着「点击左侧图表中的书籍」，
非得再点一次才有内容。

**根因**：`advState.selectedIds`（「哪些书的详情卡展开着」）初始是 `[]`，所以右侧必然落在空态分支；
展开详情的唯一入口是柱状图/折线图上的 `click`。

**改法**：`advState` 加两个字段，只动一个已有的取值函数，不新增渲染路径。

- `drillAuto: true`——「详情卡跟着图上的书走」。`liveSelectedIds()` 在这个模式下直接返回
  `getAdvComputed()` 现有的全部书，所以**图上画了几本，右边的卡就铺开几本**。选布尔量现算而不是
  「初始化时往 `selectedIds` 里塞一次」，是因为后者会在换「观察角度」（`initAdvancedData` 重跑）
  或增删书名之后与图脱节；现算永远和左边一致。
- 用户手动点过任意一下（`advDrillDown` 或卡片上的「✕ 收起」），`freezeDrillAuto()` 把自动态**固化**
  成一个显式集合再按点击增删；`重置视图` 把它恢复成 `true`。少了这个固化，自动模式下点「✕ 收起」
  会点了没反应（下一帧又被自动态铺回来）。
- 自动模式下 `updateHighlightVisuals()` **不压暗也不点亮**：每本书的卡都开着时「选中」等于没有重点，
  全点亮反而让整页看起来都是选中态。

**顺带做了悬停预览**：鼠标停在左边哪根柱子/哪个点上，右边就临时只显示那一本；移开回到原来那几本。
它只挂 `previewId`，**不写 `selectedIds`**，所以移开就回去。两个图共用 `advHighlight` / `advUnhighlight`
这一对钩子，一处改动两张图都生效。预览时播报显式关掉（`announce: false`）——否则鼠标划过每根柱子
都会触发一次 `aria-live` 播报，读屏用户会听到一长串重复。

**同时删掉一句假话**：空态原来写「点击左侧图表中的书籍，或拖拽走势图查看段落详情」。后半句是假的——
框选只改 `brushRange`，它会更新**已展开**卡片的内容，但**不会展开任何一本**。现在按情况分两句：
图上一本书都没有 →「上方还没有选中任何一本书。先点书名，这里就会列出它数值最高的几个片段。」
有书但全被收起 →「已收起全部书籍。点左侧任意一根柱子或折线，可以再展开。」

### 4. 导出工具条分主次（视觉层级，桌面端**省 0px**）

原先 6 个按钮平铺、权重完全相同。真正常用的只有「导出图像」和「复制此链接」，其余 4 个
（矢量图/数据表/摘要/引用）收进 `<span id="export-more" class="export-more" hidden>`，
由新增的「更多导出 ▾」切换，带 `aria-expanded` + `aria-controls`。这是仓库里**第一处**
`aria-expanded` 用法（此前省空间的手段只有 `title`、`hidden`、`.visually-hidden`），用标准属性、不发明新写法。

`.export-more { display: contents; }` 让这层 span 对 flex 布局隐形：展开时里面 4 个按钮直接成为
`.export-group` 的 flex item，跟外面 2 个同排、沿用父级 `gap: 8px`；收起时靠仓库既有的
`[hidden] { display: none !important }` 整块消失，**同时自动退出 Tab 序列**。

**省多少要说实话**：桌面宽屏本来就是一行，同一次量下来工具条高度改前改后都是 **33px，省 0px**；
手机端 6 个按钮会折成 2–3 行，能省 30–60px。所以这一项的主要收益是**视觉层级**，不是高度。

## 🔧 补充说明：「线上演示站仍跑在旧构建上」这句话是错的（2026-09-28）

上一节最后一条，以及前面几个批次里同一句话的重复（核对时位于第 407、532、706、794、896 行），
**都与线上实际的上线方式矛盾**。按本仓库「只追加、不改已有行」的规矩，上面一行不动，只在这里更正。

**线上不是「躺着等一次手动重新部署」，而是一条自动部署链路：**

- 服务器是阿里云 ECS `39.96.194.197`，`/opt/literature-fingerprinting` 就是本仓库 `master` 的一个
  git checkout（`origin` 走 GitHub HTTPS）。
- root crontab 每 2 分钟执行一次 `/usr/local/bin/literature-autodeploy.sh`：先
  `git fetch origin master`，**若 HEAD 已经等于 `origin/master` 就直接退出、连服务都不重启**；
  否则 `git merge --ff-only FETCH_HEAD` 再 `systemctl restart literature-fingerprinting`。
- 脚本带 `flock` 防重叠，日志写在 `/var/log/literature-autodeploy.log`。

所以**向 GitHub master 推送后 ≤2 分钟内线上就是最新**。每次真正部署会重新处理那 4 本内置书，
约 1–3 分钟 CPU 忙、期间访问偏慢；ff-only 失败时脚本只记日志，需要人工介入。

**这个错是怎么来的。** 上述部署信息记在本机 `Desktop\简历整理\修改.md` 的第 93、94 节（09-10），
**不在本仓库内**，所以此前写 README 时看不到它，就照抄了「需要重新部署」这个想当然的说法。

**还没核实的一点，如实说明。** 以上是**文档记载**，本次没有真的登上服务器去核对当前 HEAD、
服务状态与 crontab——那一步没做。也就是说「自动部署确实在跑、线上已经是最新」目前的状态是
「机制存在且文档如此记载」，不是「已亲眼确认」。要下断言之前，应当先上机看一眼。
