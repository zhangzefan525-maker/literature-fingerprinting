# 文学指纹 · Literature Fingerprinting

> 不用写代码，也能一眼看懂「不同作家的写作风格差在哪里」。

## 📖 产品介绍

### 这是什么？

「文学指纹」（Literature Fingerprinting）是 Keim & Oelke (2007) 提出的一种方法：把一部小说切成一段一段，计算每一段的平均句长、词汇丰富度等特征，再把这些特征画成像素块和交互图表。每个作家写作的习惯不同，画出来的「指纹」也就不一样——于是你就能直观地看到他们风格的差异。

本项目把它做成了一个开箱即用的网页工具：基于 Python 计算 + D3.js 交互图表，全程可视化操作。

### 能做什么？

- **分析自己的书**：上传任意一部英文小说（`.txt`），几秒钟生成它的「文学指纹」。
- **和名著对比**：与内置的 4 本示例名著（马克·吐温、杰克·伦敦各两本）并列对比。
- **层层下钻**：拖拽、点击、悬停，一路深入到具体段落，看这本书的高潮在哪、哪段最特别。
- **留存自己的分析**：勾选「存入我的图书馆」，上传的派生指纹会保存为 `data/library/*.json`，刷新后仍在，可随时用书名旁的 ✕ 删除（内置示例书不可删，重名会自动改名、不会覆盖）。
- **出处定位与复制**：每个数据点都标注「第 X/N 块 · 约全书 Y% · 本块词数」，可一键复制原文片段用于写作引用。
- **带范围的解读**：指标提示给出按当前已加载书籍算出的参考区间（随数据变化），Honoré 等指标附「宜同尺度横比」的提醒，避免把裸数字当绝对标准。

### 适合谁？

文学研究者、语言学习者、读书爱好者，以及任何想「用数据看文学」的人——**全程不需要写任何代码**。

## 🚀 基本使用步骤

1. **启动**：双击 `start.bat`。
2. **等待**：脚本会自动准备示例数据（首次运行约 1-2 分钟），然后自动打开浏览器。若页面还没加载出来，稍等几秒刷新一次。
3. **看示例**：页面顶部已内置 4 本名著，直接点击书名即可查看它们的指纹。
4. **分析自己的书**：点顶部的「上传文本分析」，选一个英文 `.txt` 文件，几秒后它就会出现在书名列表里，和示例书并列对比。想留档就在「上传」旁勾选「存入我的图书馆」（本地版默认勾选，在线演示默认不勾）——之后刷新页面它仍在。

## 👀 怎么看这些图

1. **选书**：顶部点书名（可一次点多本），图表会自动变成多本书并排对比。
2. **看局部**：在右下角「趋势演变」图上按住鼠标左键左右拖拽，选出一段（比如某个章节），左边所有图会立刻只显示这一段的数据。
3. **看细节**：点任意柱子或线条，右侧会弹出这本书在这一段里数值最高的 3 个段落，附原文片段和关键词。
4. **排序与高亮**：点图表标题旁的排序图标可切换排序；鼠标悬停任一元素，相关的书会被高亮、其余自动变暗。

## 📊 这些指标是什么意思

- **平均句长（Average Sentence Length）**：一句话平均多少个单词，数值越大句子越长、越书面。
- **辛普森指数（Simpson's Index）**：词汇丰富度，越接近 0 用词越丰富，越接近 1 越重复。
- **Honoré 词汇丰富度 R（字段名仍为 Hapax Legomena）**：由词元总数 N、不同词型数 V 和只出现一次的词型数 V1 综合计算，当前实现公式为 `R = 100 × ln(N) / (1 - V1/V)`。它通常不是 0–1 的比例；数值越高，一般表示词汇使用越丰富。
- **功能词 PCA（Function Words PCA）**：看「的 / 和 / 是」这类高频小词的使用习惯，反映语法风格。

## ⚠️ 注意事项

- **只支持英文文本**：目前算法按英文设计，中文等其他语言的结果不可靠。
- **文件格式**：请用 `.txt` 纯文本，UTF-8 编码。
- **文本长度**：正文至少约 1 万词，建议几万字——书越长，趋势图越丰富；太短会无法生成指纹。
- **首次运行较慢**：第一次启动要生成示例数据，约 1-2 分钟，之后秒开。
- **页面打不开**：若浏览器没自动打开或页面空白，稍等几秒刷新；若仍不行，可能是 5000 端口被占用，关闭占用程序后重试。
- **隐私与留存**：上传属于即时分析。只有勾选「存入我的图书馆」后，派生指标与片段预览（长片段预览可大段覆盖原文）才会写入当前服务器的 `data/library/`：本地版默认勾选（本机留档），在线演示默认不勾（不落盘，重新部署还会清空）。内置示例书永不会被覆盖或删除。当前在线演示使用 HTTP，不应视为加密传输，请勿上传敏感、私密或未获授权的文本。

### 本地开发

环境要求：Python 3.10+（开发与测试环境为 Python 3.13）。

```bash
# 1. 克隆项目
git clone [repository_url]
cd Literature-Fingerprinting

# 2. 安装依赖
pip install -r requirements.txt

# 3. (可选) NLTK 数据包会自动下载，如遇网络问题可手动运行：
# python -c "import nltk; nltk.download('punkt'); nltk.download('stopwords')"
```

**手动启动**：预生成示例数据（服务器在首次请求时也会自动生成）：

```bash
python generate_data.py
```

再启动 API 服务器，然后访问 <http://localhost:5000/visualization>：

```bash
python api_server.py
```

**运行测试**（指标 + 书库 API 全套）：

```bash
python -m unittest discover -s tests -v
```

**删除「我的图书馆」里的书**：删除需要保存时签发的令牌（存在保存它的浏览器里），
本机也一样——`Host` 头是客户端说了算的，拿它当删除授权等于没授权。
清过浏览器数据、又想删掉本机的旧文件时，可以显式开启本机豁免：

```bash
# Windows (cmd)
set ALLOW_LOCAL_DELETE=1 && python api_server.py
# macOS / Linux / Git Bash
ALLOW_LOCAL_DELETE=1 python api_server.py
```

或者直接删掉 `data/library/<书名>.json`。

**Streamlit 经典模式**（⚠️ 已归档，仅作实验性参考；正式产品为上方 D3 版，新用户无需关注）：

```bash
streamlit run app.py
```

## 🔧 变更记录：界面文案纠错与两个渲染缺陷（2026-09-27）

这一批只做「说错的话」和「会坏的地方」两件事，不动配色、不动算法、不动任何指标口径。

**说错的话。** 界面在四个地方告诉用户风格星系的坐标是按中文虚词「的、和、是」算的，
但语料是英文小说，真实模型用的是 `the / his / of / he`（横轴）与 `and / he / you / that`
（纵轴），而且同一页下方的图注早就在显示这组真实的英文词——页面自己打自己。
现在轴词例子改为从后端 `projection.axisLabels` 实时取用，取不到时只说「高频小词」、
不编例子。另一个错误是「独特词丰富度」被描述成「占比」：它实际是
`R = 100 × ln(N) / (1 − V1/V)`（本书 52 行的写法才是对的），实测区间 1725–2516，
按「占比」去读会差一个数量级，三处文案已按 52 行的口径改写。
另外还修了「区域平均平均句长」的叠字、什么都说明不了的图例「一端 / 另一端」、
以及风格星系面板里书名显示成截断英文（`The Call of the …`）而别处显示《野性的呼唤》的不一致，
CSV 第一列的书名也一并统一成中文名。

**会坏的地方。** 风格星系在缺高频小词数据时引用了一个从未声明的变量，抛出异常后
画布已经清空却没有任何说明，还会把一次成功的上传误报成「上传失败」；
折线图不会清除上一次热力图留下的行内高度，书少时（含默认的单本）图会缩在一片空白中间、
导出的 PNG 也跟着大半张空白；首次加载慢时先完成的上传会被后到的整份数据覆盖掉；
全书对比页的导出按钮写死了「整体水平对比」，导致「风格走势」那张永远导不出来。
四条都已修复。顺带删掉了页面上一个从未被写入过的空图例盒子（`#legend` 及其 CSS）
和一个无人调用的 `toggleMetric()`。

**上面 53 行那条例句（「的 / 和 / 是」）与本批修的是同一个错误，但按「README 只追加」
的约定，那行原文保留不动，仅在此说明。**

## 🔧 变更记录：绘图边界的五处越界与手机端三处遮挡（2026-09-27）

承接上一批，这一批只修「画出来的东西是错的」和「小屏上点不到」，同样不动算法与任何指标口径。

**坐标轴上下界。** 折线图用乘法给纵轴留白（`extent[0] * 0.95`、`extent[1] * 1.05`），
乘法对负区间方向是反的：区间全负时下界反而被抬高、上界被压低，可视窗口比数据本身还窄。
「风格走向」的横坐标是 PCA 有符号值，内置书里本来就是负数（实测 −0.0597 ~ −0.0169），
于是 102 个片段里有 12 个被画到横轴下方、最高的那个点顶进图标题。改为按本跨度做加法 padding，
正负区间都是往外撑，实测越界点数由 13 降到 0。

**热力图画布高度。** 每本书的格子边长按它自己的 `cols` 各算各的，旧代码却拿第一本的格子边长
去乘全局最大行数。只要后面某本书的格子比第一本大，它的网格就会伸进下边距，
图例条和「虚线是章节分界」那行说明正好压在最后一排格子上。改为逐本算出 `rows × blockSize`
再取最大值，两本书的对照用例下网格底 336、图例 438、章节注 470，重叠消除。

**导出。** 导出的 SVG 里原本没有 `.zero-line` / `.annotation-point` / `.selection` 规则，
读者拿到的图会丢掉零线、标注点和框选框；两张图各自内联一份样式表也容易漂移，
现在合并为单一常量。同时补上了导出图例：仪表盘导出的图会带书名色块，星系导出会带
图例和轴说明，星系那张的轴说明实测按 2 行折行。热力图配色另有一处对比度问题——
图例上「低 · 短句」的墨色直接用了色阶端点（#7f9dc4，对比度 2.66:1，低于 AA），
改为深色墨（实测 rgb(44,74,110) / rgb(143,29,22)）。

**手机端遮挡。** 提示框用绝对定位贴在光标右下，靠近右边缘时被浏览器压成 73px 宽的竖条
（实测旧行为），现改为 `position: fixed` 并按视口宽高钳制，真 390px 视口下实测 206×123、
右边界 382 未溢出。「停止文本雨」浮动按钮固定在右上角，在 320px 宽度下正好压住吸顶的
页签栏——实测两者重叠 1777px²，且页签中心的 `elementFromPoint` 命中的是按钮而非页签，
点「风格星系」会误触发文本雨；现移到右下角，重叠归零、命中回到页签本身。

**框选范围说清楚。** 在「风格走势」上框选后，卡片标题、解读、提示框都只统计框选区段，
但文案没有任何说明，读者会把它当成全书水平。现在标题带出「（框选区段 0.0%–30.0%）」，
解读首行说明「只统计框选区段，不是全书」，而异常对比那句仍然按全书平均比，
并显式标注「不受上方框选影响」。

以上全部为工作区未提交状态；`src/` 与 `api_server.py` 一行未动，`python -m unittest discover -s tests`
仍为 147 项全过。

## 🔧 变更记录：数值口径统一、离线可用与一处自相矛盾（2026-09-27，第二批）

**悬停提示框印原始浮点数。** 同一文件里那句「四个出口（详情面板 / 图注 / 摘要 / 悬停）口径一致」
是实现者的原意，但悬停这个出口写的是 `escapeHtml(data.value)`，直接把 JSON 里的原值印出来：
「风格走向」的一个片段悬停显示 `-0.019992956022007756`（21 位），点开详情却是 `-0.020`。
四本内置书的四个指标全都如此（`25.1692` vs `25.17`、`0.011755` vs `0.0118`、`2075.0013` vs `2075`）。
现改为统一走 `formatMetric`；顺带把风格星系的调用点从「先格式化再传字符串」改成传原始数值，
否则字符串会命中 `formatMetric` 的 `!isFiniteNumber` 分支、四个出口里三个显示「暂无」。

**d3 改为本地副本 + CDN 兜底。** 整页的图表与全部交互都建在 d3 上，而它一直从 `d3js.org` 取；
那个域名取不到就是整页不出图、页签也切不动。现在仓库里带一份 `static/js/vendor/d3.v7.min.js`（v7.9.0），
优先走本地、不发网络请求；万一本地副本缺失，下一行会在 `window.d3` 为空时补一份 CDN 的
（实测：临时移走本地副本后 `d3js.org` 那份被拉起来，`d3.version` 仍是 7.9.0）。
图标字体仍是 CDN——只有 8 个装饰性图标，取不到时 `<i>` 渲染成空元素，不影响功能。

**全书对比页的提示框被挤成竖条。** 这个页签的提示框是另一个元素（`#adv-tooltip`），样式全写在 JS 里，
只写了 `left: pageX+10`。绝对定位元素的宽度由「容器剩余宽度」决定，320px 下悬停走势图最右那个点，
可用宽度只剩 44px，提示框被压成 **47×140** 的窄竖条（一次只显示一个字），还把页面撑出横向滚动条。

## 🔧 变更记录：风格星系的轴说明说反了一半（2026-09-27，第四批）

**问题**：风格星系图下面那两行轴说明，横轴是对的，纵轴四个词里有两个说反。

`src/projection.py` 的 `axis_labels()` 按每个主成分**载荷的绝对值**取前四个词，再套一句
「越靠右／上，这些词占比越高」。但载荷是**带符号**的：正负代表坐标轴上相反的两端。
一句话只能管一个方向，把两种符号混进同一句，混进来的那一半无论比例尺朝哪边都必然说反。

实测 `pca_model.json`：

| 轴 | 取到的前四词（载荷） | 结果 |
|---|---|---|
| 横轴 PC1 | the +0.556 ／ his +0.340 ／ of +0.298 ／ he +0.280 | 全是正号，**原本就对** |
| 纵轴 PC2 | and +0.770 ／ he +0.263 ／ **you −0.217** ／ **that −0.177** | 混进两个负号，**and 和 he 说反** |

还有第二处错：`static/js/d3-charts.js` 里星系的 `yScale.range([padding, height - padding])`
把数值大的一端放在**下方**（SVG 的 y 向下增大），文案写的却是「纵轴越靠**上**」。
两处错部分互相抵消，最后表现成「四个词里两个对、两个错」。

值得记一笔：**星系根本没画坐标轴，也没有刻度**（`axisLeft` 只在折线图里出现），
所以这两行字是全图唯一告诉用户「上／下是哪个方向」的东西，说错了没有别处能纠正。

**试过但否掉的改法**：把星系的 y 比例尺翻过来，与折线图同向。实测翻完之后**仍然是四个词错两个**，
只是错的那半从 and／he 换成了 you／that——翻朝向只能决定「哪一半错」，消不掉错误。
代价却是把星系整体上下镜像：此前导出的每张 PNG、分享出去的每张截图都不作数了。
而 PCA 主成分的正负号本来就是任意的，坐标轴并没有「值大＝更多」的语义，
为一个无含义的方向付这个代价不划算。

**实际改法**：`axis_labels()` 改成按载荷**符号分组**，一段只说同号的词：

- 横轴越靠右，the / his / of / he 这类小词在整段里占的比例越高　←　逐字未变
- 纵轴越靠下，and / he 这类小词在整段里占的比例越高；纵轴越靠上，you / that 这类小词在整段里占的比例越高

- `getAxisWordsFor()` 取轴词的正则原来没有 `g`、词表字符类也没排除分号，只看得到第一段；

- 导出图里轴说明的折行原来**两处各写各的**：算高度用 `Math.ceil(len/46)`，画文字用 `i += 46`
  且硬顶 4 行——说明超过 4 行、或长度不是 46 的整数倍时两者就对不上，图例带会盖住图或多出一截空白。

### 1. 解读里的「参照」和它左边的数字不是同一个口径（说假话）

框选生效时，解读面板会先声明「下面这些数字只统计走势图上框选的 X%–Y% 区段，不是全书」。
但紧跟其后的参照句，是拿**其它书的全书平均**去减**本书的区段平均**，再把差值说成
「这本书比它们低于约 X」——一本的区段数减另一批书的全书数，差没有含义。

实测（哈克贝利·费恩，用词重复度，框选 20.0%–50.0%）：

| | 数值 | 后果 |
|---|---|---|
| 本书·框选区段平均 | 0.0106 | — |
| 参照·其它 3 本**全书**平均（旧） | 0.0118 | 报「低于约 0.0012」 |
| 参照·其它 3 本**同区段**平均（新） | 0.0123 | 报「低于约 0.0017」 |

差被少报了约四成。新增的 `bookSegmentValues()` 用与 `initAdvancedData` 完全相同的口径
（`xPercent = i / (片段数 − 1)`、剔掉非有限值、套同一个区间）给其它书取数，参照句也写明
「在框选的 20.0%–50.0% 区段内平均约为 …」。顺带修掉一处小的：旧代码没剔非有限值，
而 `initAdvancedData` 剔过，所以参照数和走势图上画出的线本来就不是同一批数。

### 2. 取消勾选一本书之后，整页停在 12% 不透明度（会坏）

`advState.selectedIds`（哪些书的详情卡展开着）和 `selectedBooks`（图上有哪些书）是两份状态。
用户取消勾选一本书时只动后者，前者会留着一个图上已经不存在的 id，于是
`updateHighlightVisuals()` 把**每一本**都调暗、再去点亮那本已经不存在的书——
一本都没亮，整页发灰；详情卡也还挂着一本不在图里的书。

同一状态下新旧逻辑的实测对照（`.book-el` 共 3 个）：

| | 调暗数 | 点亮数 |
|---|---|---|
| 旧逻辑（不过滤） | **3** | 0 |
| 新逻辑（过滤后） | **0** | 0 |

新逻辑把过滤后为空的选择当作「没选」，整页恢复常态、详情卡回到空提示。
用**过滤**而不是从 `selectedIds` 里删，所以重新勾选这本书时详情卡会自动回来（已实测）。

- 重画清单加上 `updateDrillPanel()`；
- `advMeanLabel()` 带上指标名 → 「平均句长」「区段平均句长（20.0%–50.0%）」。

### 5. 横轴写着「阅读进度」，可它不是进度（说假话）

主视图折线图的 `xScale` 定义域是 `[0, maxBlocks]`，每本书按**自己的**片段序号画
（`.x((d, i) => xScale(i))`），而各书片段总数差 4.6 倍（野性的呼唤 22 个、哈克贝利·费恩 102 个）。

这里也没有做任何归一化，所以连「百分比」都不能叫。原来那句
「阅读进度（每个片段约 1 万个单词）」会让人把两条线在同一个 x 上直接对比，读出不存在的结论。
改成两行：

```
片段序号（每个片段约 1 万个单词）
各书片段总数不同，同一个序号不代表相同的阅读位置
```

（看板页的走势图才是归一化到 0–100% 的，那里「阅读进度」的说法保持不变。）

## 🔧 变更记录：同名的三种结局、看板的键盘通路与四处口径（2026-09-27，第六批）

> **先更正本文档自己的一句话。** 上文「能做什么？」一节写着「重名会自动改名、不会覆盖」。
> 这句与服务端 `_resolve_final_name()` 的行为**正好相反**：书库里已有同名时它沿用的是同名、
> **原地替换**，上一版分析就此消失。按「README 只追加、不改旧行」的约定，那句保留在原处，
> 特此作废，以本节为准。（页面上那条一模一样的 tooltip 已按实情改写。）

### 1. 同名的三种结局，以前一种都不说

同一个文件名，落到磁盘上有三种完全不同的结果，而界面上给的是同一句「分析完成」：

| 情况 | 服务端做的事 | 用户以为的 |
| --- | --- | --- |
| 撞上内置示例书名 | 另存为《X（我的）》，示例书不动 | 我传的这本进去了吗？ |
| 撞上书库里已有的同名书 | **整份替换**，上一版分析消失 | 我在「新增」一本 |
| 没勾选保存、但书名重名 | 磁盘上留着的还是旧的那本 | 书库里那本已经更新了 |

现在响应里带 `renamedFrom` / `replacedExisting` / `shadowsExisting` 三个字段，
`handleFileUpload()` 按情况把话说在完成提示后面。CDP 走 `<input type=file>` 的真实文件选择
路径实测四条，逐字如下（每条分析 2.7–3.1 秒）：

1. 全新名字 + 勾选 →「『lit6-重名测试』分析完成，共划分 23 个片段。已存入「我的图书馆」，刷新后仍在，可点书名旁 ✕ 删除。」（无附加句）
2. 同名再传一次 →「…**书库里同名的《lit6-重名测试》已被这次的结果整份替换，上一版分析不再保留。**」
3. `White Fang.txt`（撞内置《白牙》）→「…**《白牙》是内置示例书的书名，这次存为《White Fang（我的）》，示例书不受影响。**」
4. 取消勾选后再传同名 →「…本次未勾选保存，刷新后不会保留。**书名和你已保存的《lit6-重名测试》重名：屏幕上显示的是这次的分析结果，书库里存着的仍是上次保存的那一份（这次未勾选保存）。**」

勾选框的 tooltip（`d3_visualization.html`）随之照实重写，`_resolve_final_name()` 的 docstring
也补上了「注意 1) 是**会毁掉旧数据的**」。

### 2. 落盘失败不再连分析结果一起丢

「我的图书馆」写入失败时，原来直接返回 500 且不带 `data`，前端据此提前 return，
文案却说「请改在上方展示区查看」——指向一个根本不会出现的书名；用户唯一能做的就是重传一遍，
而磁盘问题没解决必然再失败一次。高成本的那一步（几秒的全书分析）已经跑完了，不该丢掉：
现在照样下发结果（`saved=false` + `warning`），图上能正常看，只是刷新后不留存。

### 3. 单次分析的片段数有了上限（600）

50 MB 只是「文件字节」这道闸门，换成英文正文能装下几百万词，而分析开销随片段数线性增长。
上限拦在 `build_book_data()` **之前**（拦在后面正是要避免的那段等待），报错说清三件事：

> 文本太长，单次最多分析约 600 个片段（覆盖约 60 万英文单词），这份文本约 848 个片段。请拆分文件后分次上传，或先截取要研究的那些章节。

（「覆盖约 60 万词」按 `(600-1) × (10000-9000) + 10000 = 609000` 算，不是「片段数 × 1 万」——
片段之间重叠 9 千词。）

### 4. 把摘录当全文说

一个片段约 1 万个英文单词，弹窗里给的始终是开头的 1200 字，而那一节的标题叫
**「原文深度阅读」**、按钮叫**「复制全文」**。把摘录当全文引用出去，是读者看不出、作者会吃亏的
那种错。现在标题是「📜 原文片段」、按钮是「⧉ 复制这段摘录」，正文上方多一行 `#modal-text-note`：

> 本片段共约 10,000 个英文单词，此处显示开头 1200 个字符（约占 2%），不是全文。

字数按**真正显示出来的**字符算（`_preview()` 补的三个点不算原文），所以老数据只带 150 字摘录时
不会写成 1200。卡片里那个「复制片段」同理改成「复制摘录（1200 字）」，并加一句 `.excerpt-note`
说明引文比复制到的短。

### 5. 四个指标的摘录长度本来不一致（后端）

`build_book_data()` 里只有 `functionWords` 带了 `extended_preview`（1200 字），
另外三个只有 `preview`（150 字）。于是**同一个片段，只换一下「观察角度」**，弹窗里的原文就从
1200 字缩成 150 字——而标题和按钮都自称全文。现在四个指标统一走 `_block_entry()`，
`CARD_PREVIEW_CHARS = 150`、`MODAL_PREVIEW_CHARS = 1200`。

### 6. 看板页的钻取与框选只能鼠标

「哪一段偏离得厉害」正是从片段详情卡里读出来的，而柱子和折线都是不可聚焦的元素，
键盘用户在看板页打不开任何一本书的详情；框选（区段平均的唯一入口）更是 d3.brush 的纯鼠标操作。

- `attachDrillKeyboard(nodes)`：整张图只留**一个** Tab 停靠点，进去之后方向键逐本走、
  Home/End 到两端、Enter/Space 展开，`role="button"` + 带书名/指标/数值的 `aria-label`。
  走法沿用图上别处已经做好的那套，避免几十根柱子各占一个 Tab。
- `attachBrushKeyboard(g, brush, w)`：方向键平移整个框（每次 1% 宽）、Shift + 方向键收放右边界、
  Esc 清空；还没框过时第一次按键先划出中间一段，用户不用凭空知道该按哪边。
- 顺带修掉一个**上一批自己引入的错误**：`bars` / `paths` 是 `.data()` 的 **update 选择集**
  （首屏渲染时它是空的），键盘必须挂在 `.join()` 返回的合并集上；挂在 update 集上等于
  首屏一根柱子都点不到。鼠标能点是碰巧——`.on()` 链在 `join()` 的返回值上。实测修复后
  4 根柱子、4 条折线都带 roving `tabindex` 与 `role="button"`。

### 7. 「✕ 收起」之后焦点掉回 body

被点掉的那个按钮正是刚被重建掉的节点，键盘用户按一次回车就迷路了。现在把焦点接到
`#adv-drill-content`（带 `tabindex="-1"`，再往下 Tab 一次就回到还没收起的卡片按钮上）。
这一块同时补了播报：它以前**不出声**（同屏的 `#insight-content` / `#anomaly-content` 都带
`aria-live`），但整块做成 live region 会把卡片里的按钮和关键词一起念好几遍，
所以内容区只当普通区域（`role="region"` + `aria-label`），另设视觉隐藏的 `#adv-drill-announce`
（`role="status"`）播一句话：

> 已展开 2 本书的片段详情：《哈克贝利·费恩历险记》、《野性的呼唤》，每本列出数值最高的 3 个片段。

`updateDrillPanel()` 也顺手改了写法：原来是每本书一次 `panel.innerHTML +=`，有几本书就整块
重建几次——屏幕上闪，live region 也跟着报几遍；现在是拼好一次写入。

### 8. 系统里关了「减少动态效果」，页面照样满屏飞

`prefersReducedMotion()` 以前只用来决定文本雨的默认开关，而页面里真正会动的东西——d3 的全部过渡、
风格星系每次进入那场约 5 秒的力导向收敛——一条都没走这个判断。新增 `motionDuration(ms)`
并接入所有 d3 过渡（`d3_visualization.html` 里那个脚本用 `animMs()` 转发，免得到处写 `typeof`）。
压成 **0 而不是「不动」**：不动的话柱状图会停在上一次的旧高度上。星系则在
`prefersReducedMotion()` 时先在内存里 `tick(120)` 再一次性画出来——`tick()` 不触发 `"tick"` 事件，
所以算完必须手动调一次 `ticked()`，否则屏幕上是一片空白。

### 9. 星系每次进入都从零重跑力导向

切页签、换指标、换书、拖窗都要重看一遍那场约 5 秒的抖动，用户手动拖开的那几个点还会被拉回原位。
现在 `galaxyPositions` 记下落点，下次进入从上次的稳态接着算（`alpha(0.35)`、`alphaDecay(0.06)`，
不再从 `alpha=1` 退火）；只在落点仍落在这一屏里时才用——换了几本书坐标尺会整个变，
旧点位跑到屏外反而要花更久才被拉回来。「↻ 重新布局」按钮先 `galaxyPositions.clear()`，
它「真的重新排一次」的承诺因此不受影响。实测：清缓存重进，第一个点位与上次记录的坐标
逐位相同（0.0px）；普通重进则相差 4.4px（力导向确实接着算了，而不是原样复读）。

### 10. 320px 下热力图图例的「低 · 」被裁在画布外

色带宽度写死 220，两个标签又各贴着色带往外排 10px：在 320px 宽的屏幕上左端只剩「短句」，
「低 · 」整个落在画布外，读者只看到右端有「高」，左端是什么就没了对照；换成「独特词丰富度」

### 11. 导出的条形图丢了口径说明

### 12. 触屏上教用户「滚轮缩放」

手指没有滚轮，也没有「悬停」。两句提示都写在 HTML 里，由 CSS 按 `@media (hover: none)` 择一显示

## 👆 变更记录：手指上的可点面积、摘录口径与最后一处外链（2026-09-27，第七批）

上一批末尾那份「没做的」清单，这一批逐条清掉；同时把其中两条**先量了一遍**，
发现有一条已经不成立、另一条的数字要改口——都写在下面。

### 1. 触摸目标：17 个小于 44×44 → 控件 0 个

320×760、开触摸模拟实测，页面上有 17 个可点元素小于 44×44。现在用一个 `@media (pointer: coarse)`
把它们撑起来：页签、快速开始、导出按钮、书名 chip、筛选芯片、排序控件、复制按钮、「存入我的图书馆」、
下拉框给 `min-height: 44px`；弹窗右上角的 `×` 给足 44×44；书名旁的删除钮只撑**命中区**（见下）。

为什么用 `pointer: coarse` 而不是 `max-width`：这里要表达的是「输入是手指」而不是「屏幕窄」。
平板横屏不窄，带触摸屏的笔记本主指针却是触控板（`pointer: fine`）——按宽度写，这两种情况都会判错。
放在样式表最后，是为了压过上面那些按宽度写的移动端微调（例如 ≤560px 里把 `.cyber-btn-float`
压成 `padding:5px 11px` 的那条），否则同一条属性谁在后面谁赢。

**「停止文本雨」93×28 与「上传文本分析」154×42 是第一次漏掉的**：前一版只按「按钮」这个直觉挑选择器，
漏了这两个类名不同的（`.cyber-btn-float`、`.upload-btn`）。复量时才发现，一并补上。

**删除钮的命中区**：`.book-del` 实测 38×22。它做的是删除，改小不行、改大会盖住旁边的书名 chip
（变成「想选这本却删了那本」），所以只撑竖向、横向不动，用 `::before` 撑到 44px——正好是
`.book-group` 的高度，一格不越界。这里有个坑：**定位伪元素的参照物是 padding box，而 `.book-del`
有 1px 的透明边框**，所以 `top/bottom` 给 −11px 只能得到 42px，必须给 −12。
（`getBoundingClientRect()` 量不到伪元素，验证得用 `elementFromPoint` 打车上下边缘的点；
上一版我据此以为「向下没撑到」，其实是探针正好打在半开区间的边界那一像素上。）

### 2. 摘录字数：两处一个算法

同一段摘录，卡片按钮写「复制摘录（1200 字）」、弹窗按钮写「复制这段摘录（1203 字符）」。
差 3 是因为卡片按 `_preview()` 补的省略号扣掉再数、弹窗按原始长度数；「字」与「字符」混用是因为
正文是英文，说「字」本来就不准。现在统一成 `excerptCharCount()`：**只数真正复制到的正文字符**
（省略号是界面加的，不是原文），单位一律「字符」，两处都从这一个函数取。

### 3. `clean_text()` 的贪婪正则：单行输入会把正文清光

原来起始标记用 `.*`（贪婪、默认不跨行），只会在**同一行里**一路吃到最后一个 `***`。
正常的多行文本两种写法结果相同；但 `START` 与 `END` 落在同一行时（复制粘贴丢了换行、
或整本书被拼成一行），`start_match.end()` 会跑到 `end_match.start()` 之后，切片变成空串——
整本书的正文被清光，用户只看到「清洗后没有剩余正文」，完全看不出是自己那份文件的换行没了。

改成非贪婪 `.*?`，并补一道 `start_match.end() < end_match.start()` 的顺序保险（两个位置万一颠倒，
宁可不切：少剥一层页眉只是数值略有偏差，切光了是什么都没有）。同时收下老版标记的
`THIS PROJECT GUTENBERG` 写法——原来只认 `THE`，这类文件的页眉页脚会整段留在正文里，
而界面与导出都写着「文本经页眉页脚清理」，那句话就成了假话。

**四本内置书的清洗结果逐个对过 sha256，字节级不变**（568322… / 390259… / 175204… / 396310…），
即老语料的行为严格没变；退化用例新增 3 个测试（单行标记、`THIS` 标记、标记顺序颠倒）。

### 4. 最后一处 CDN：图标字体随仓库带

`font-awesome` 6.0.0 仍在从 CDN 引：离线或校园内网打开时，8 个图标一个都不显示。d3 从第三批起
已经是仓库内的本地副本，留这一个外链等于整站还是「联不上网就掉东西」。现在同版本随仓库带一份
（`static/vendor/fontawesome/`，`all.min.css` + 4 个 `woff2`，共 352K；`.ttf` 是老浏览器的后备，
没带，现代浏览器都用 woff2）。

### 5. 术语与标点

导出摘要里写「共分析 N 本书、M 个**文本块**」，而界面上另外 110 处一律叫「片段」（「第 3 个片段」
「切成 102 个片段」「参与统计的片段数」）——同一份导出里两种叫法。统一成「片段」，
紧接着那句「按每块 10000 词、相邻块重叠 9000 词」也一并改口。
全文扫过一遍半角/全角括号、逗号、冒号混用，没有发现真问题（命中的都是 HTML 属性引号）。

### 6. 配色与对比度：实测下来这一条**已经不用做了**

上一批把「配色/对比度」列成了待办，这一批先量再动手。写了个审计脚本走遍三个页签的
每一个文字节点，把祖先链上的半透明底色逐层叠到纸底色上再算对比度（**这一步很关键**：
直接拿 `getComputedStyle().backgroundColor` 的原始色去比，会把 `rgba(107,143,90,0.10)`
当成一片深绿，报出「白字压在绿上只有 1.63:1」这种假警报——我第一版就是这么误报了两处，
合成之后归零）。

结果：**三个页签、0 处文字对比度不合格**。热力图色阶在更早的批次里已经按你选的
「保持蓝红、只拉明暗」调过（两端亮度拉到 3.19:1，代码注释里记着当时为什么这么定），本轮没动。

**验证**：`node --check` 两个脚本通过；`python -m unittest discover -s tests` **151 项全过**
（148 + 新增 3；本批不动任何指标算法）；320×760 触摸模拟下用 `elementFromPoint` 复核了
删除钮命中区（上下各 21–22px 均命中）、`min-height` 之后的控件尺寸、三个页签的渲染
（热力图 102 格 / 星系 102 个点 / 看板 3 个 chip）；导出摘要实测输出

## 🔧 变更记录：同一本书终于同一个颜色、切页签滚到内容（2026-09-28，第八批）

这一批的五项有一个共同点：**都不会让程序崩，但都会让读者读错图或看不懂图**——而这正是
这个工具的目标用户（不做统计、不写代码的文学研究者）最扛不住的失败方式。第七批修的是
「说错的话」，这一批修的是「同一件事在不同页签说得不一样」和「图上一件事根本没人说」。

### 1. 一本书在三个页签里是三种颜色（本批最重要）

折线图、风格星系、看板各自建了一个 `d3.scaleOrdinal()`，**颜色表完全相同（同样 8 个色值），
但 domain 不同**：折线图与星系用「当前选中顺序」，看板用「全库顺序」。结果同一本书换个页签
就换个颜色。实测：《白牙》在星系是 `rgb(79,122,140)`，在看板是 `#a67c3d`。

阅读时颜色就是「这是哪本书」的唯一线索，一本书两个颜色等于两本书，图例跟着一起乱。

改法是新增 `colorForBook(name)`：domain 统一建在 `Object.keys(realData)`（**看板本来就在用的
那个顺序**），折线图与星系向看板看齐。这么选是因为 d3 的 ordinal 取色就是
`range[domainIndex % range.length]`，按下标算与旧行为**逐位等价**——所以看板上的配色一位都
不变，用户看到的颜色只朝「同一本书终于一致」这一个方向变。查不到书时退回确定性字符串哈希
（不引入 `Math.random()`，那条分支实际不可达，是纯防御）。

顺带清掉一处死代码：星系建渐变的循环遍历的是 `books`（图例用，含未画入的书），而圆点只来自
`plotBooks`——被跳过的书会生成一批没有任何地方引用的 `<radialGradient>`。改成遍历 `plotBooks`。

### 2. 热力图下不再藏掉「可以多选对比」那句话

原逻辑在切到热力图时把 `#toggleComparison` 一并藏了，理由写在注释里：「热力图不支持多书
对比」。**这条注释是错的**：`drawMultiHeatmap` 就是按书循环、一本书一列画的（实测选 2 本画出
85 格）。所以被藏掉的不是入口（那本来就只是一句提示语，没有点击处理器），而是**一句在热力图
下仍然为真的话**。现在只保留「曲线平滑」那一组的显隐——那个是真的没有曲线可平滑。

### 3. 「大小 = 数值高低」没说清是哪个指标

星系的位置**恒定**取「风格走向」的二维坐标，只有圆点大小跟「观察角度」下拉走。而图例那行
只写了「大小 = 数值高低」，读者无从知道是哪个指标的数值高低。现在它会写出当前指标的
名字（`大小 = 「平均句长」的数值高低`）。

**一处必须特判**：当指标恰好是「风格走向」时，横向位置用的 `pcaX` 与大小用的 `value`
**是同一个数**（后端把 PCA 第一主成分同时放进了这两个字段）。写「数值高低」会暗示这是两套
独立的编码。这种情况改写为「（与横向位置同源）」。

这句也一起进了导出的 PNG/矢量图——图会被放进论文，光看图的人更需要知道大小是什么。

### 4. 点云为什么只占画布三成宽，页面从头到尾没说

实测：1440 与 900 两种宽度下，点云的横向填充都只有 30–31%，质心明显偏左。原因是**有意的
设计**——可比时所有书共用内置示例书的固定轴范围，只选一两本时点自然聚在中间。但页面上没有
一个字解释过，读者的第一反应是「图坏了」或者「这几本书特别像」。

现在在星系说明面板里加了一句中性的补充说明。它只在**坐标可比且没有越界**时出现，写在原来的
`else` 分支内部，所以「各书各自计算」（范围不共享）、混用旧数据、没有可比书这三种情况会自动
排除，不会和面板上已有的 ⚠ 告警打架。

### 5. 切页签之后滚到内容

页签条以上压着约 630px 的标题/选书/上传/指标/快速开始/工具条，之前切页签是不滚的：
点完「风格星系」，屏幕还停在选书那一屏，得自己往下拨。现在切完页签会把该视图的顶部滚到
吸顶条下沿。

几个必须自己处理的细节：

- **吸顶条高度不是常量**（窄屏改过字号内边距，`flex-wrap` 换行后更高），所以每次实测再算 Y，
  而不是在 CSS 里写一个必然在某些宽度下遮住标题的 `scroll-margin-top`。
- **减动效的用户必须由 JS 自己问**：`window.scrollTo` 显式传入的 `behavior` 会覆盖 CSS，
  CSS 里那条 `scroll-behavior: auto !important` 保护不了这条路。
- **从分享链接进来时不滚**：那一刻数据还没到、三个视图都是空盒，而且要和浏览器自己的滚动
  还原抢，所以深链恢复页签时显式关掉滚动（`{ scroll: false }`）。
- **键盘切换时 `focus()` 加 `preventScroll`**：否则平滑滚动还在途中，`focus()` 会把页面拽回
  页签条，两个偏移打架。

**已知代价（不是 bug）**：滚到内容意味着全局工具条（导出图像/矢量图/数据表/摘要/引用/复制
链接）和指标条会被推到屏幕上方，原来是「导出按钮一直看得见」，现在是「往上滚一下才看得见」。
两者不可兼得，选了「切完页签立刻看见图」。

### 6. 实测中查出来的一个真问题：滚多了 10px

按计划断言「视图顶部 >= 吸顶条下沿」时，实测差 2px（视图 55、吸顶条底 57）——标题压进了
吸顶条两像素。

原因是 `.view-section` 每次显示都会重跑一遍 `fadeIn` 动画，而它的 `from` 状态是
`translateY(10px)`。切页签的那一刻量 `getBoundingClientRect()`，量到的是**被动画挪下去
10px 的假位置**，照着它滚就多滚 10px，正好把留的那点缝（`+8`）吃干净还倒欠 2px。

改成用 `offsetTop` 逐级相加算布局位置（`layoutOffsetTop()`）——`offsetTop` 反映的是布局盒，
动画在跑也不受影响。修完实测：视图 66、吸顶条底 57，四种路径（鼠标点、键盘方向键、
减动效、切回基础页）全部一致。

**验证**：`node --check` 两个脚本通过；`python -m unittest discover -s tests` **151 项全过**
（本批不动 Python，数量与开工时一致）。实测用的是真浏览器（CDP）：三张图的取色改成
「同一本书对调选书顺序后逐条相同」（改前星系必错）；星系首个圆点的 `fill` 指向的渐变
仍能在 DOM 里找到（证明 defs 那次改动没删错）；热力图下提示语 `display:block`、高 46px，
折线图下平滑控件才出现；星系的「大小 = …」在切换指标时正确改写、而轴说明**逐字未变**
（位置不由指标驱动），导出说明实测 6 行、未触发截断（为此把折行上限从 6 提到 7）；
点云的三种合成入参各自走到正确的分支；小视口 1000×700 下四条滚动路径全部到位；
`?view=view-galaxy` 深链加载后 3 秒仍是 `scrollY === 0`；热力图仍是连续色阶
（102 格里 88 种不同颜色，没有被 8 色污染）、文字雨仍能打开。控制台错误只有既有的

## 🧹 变更记录：首屏减重、三处重复文案与看板片段详情自动就位（2026-09-28，第九批）

前八批一直在修「说错的话」和「说不一致的话」。这一批换方向，治两件用户每次打开都会碰到的事，
外加清掉三组「同一屏里说同一件事」的引导语。取舍标准只有一条：**不减少可发现性，只减少重复和噪音**——
每一项都要能回答「删掉之后，用户会不会因此不知道该干什么」。

### 1. 看板「片段详情」默认就是满的（本批最重要）

**问题**：左侧柱状图已经把每本书都画出来了，右侧「片段详情」却写着「点击左侧图表中的书籍」，
非得再点一次才有内容。

**根因**：`advState.selectedIds`（「哪些书的详情卡展开着」）初始是 `[]`，所以右侧必然落在空态分支；
展开详情的唯一入口是柱状图/折线图上的 `click`。

**改法**：`advState` 加两个字段，只动一个已有的取值函数，不新增渲染路径。

- `drillAuto: true`——「详情卡跟着图上的书走」。`liveSelectedIds()` 在这个模式下直接返回
  `getAdvComputed()` 现有的全部书，所以**图上画了几本，右边的卡就铺开几本**。选布尔量现算而不是
  「初始化时往 `selectedIds` 里塞一次」，是因为后者会在换「观察角度」（`initAdvancedData` 重跑）
  或增删书名之后与图脱节；现算永远和左边一致。
- 用户手动点过任意一下（`advDrillDown` 或卡片上的「✕ 收起」），`freezeDrillAuto()` 把自动态**固化**
  成一个显式集合再按点击增删；`重置视图` 把它恢复成 `true`。少了这个固化，自动模式下点「✕ 收起」
  会点了没反应（下一帧又被自动态铺回来）。
- 自动模式下 `updateHighlightVisuals()` **不压暗也不点亮**：每本书的卡都开着时「选中」等于没有重点，
  全点亮反而让整页看起来都是选中态。

**顺带做了悬停预览**：鼠标停在左边哪根柱子/哪个点上，右边就临时只显示那一本；移开回到原来那几本。
它只挂 `previewId`，**不写 `selectedIds`**，所以移开就回去。两个图共用 `advHighlight` / `advUnhighlight`
这一对钩子，一处改动两张图都生效。预览时播报显式关掉（`announce: false`）——否则鼠标划过每根柱子
都会触发一次 `aria-live` 播报，读屏用户会听到一长串重复。

**同时删掉一句假话**：空态原来写「点击左侧图表中的书籍，或拖拽走势图查看段落详情」。后半句是假的——
框选只改 `brushRange`，它会更新**已展开**卡片的内容，但**不会展开任何一本**。现在按情况分两句：
图上一本书都没有 →「上方还没有选中任何一本书。先点书名，这里就会列出它数值最高的几个片段。」
有书但全被收起 →「已收起全部书籍。点左侧任意一根柱子或折线，可以再展开。」

## 🔧 补充说明：关于「线上演示站仍跑在旧构建上」那句话（2026-09-28）

上一节最后一条，以及前面几个批次里同一句话的重复（核对时位于第 407、532、706、794、896 行），
**事后核对下来是对的：线上确实没跟上**。真正查出来的是另一件事——**自动部署链路存在，但它不可靠**。
按本仓库「只追加、不改已有行」的规矩，上面几行都不动，只在这里补记。

**按设计，线上本来就应该自动更新：**

- 服务器是阿里云 ECS `39.96.194.197`，`/opt/literature-fingerprinting` 就是本仓库 `master` 的一个
  git checkout（`origin` 走 GitHub HTTPS）。
- root crontab 每 2 分钟执行一次 `/usr/local/bin/literature-autodeploy.sh`：先
  `git fetch origin master`，**若 HEAD 已经等于 `origin/master` 就直接退出、连服务都不重启**；
  否则 `git merge --ff-only FETCH_HEAD` 再 `systemctl restart literature-fingerprinting`。
- 脚本带 `flock` 防重叠，日志写在 `/var/log/literature-autodeploy.log`。

**但实测不是这样。** 2026-09-28 直读服务器上的那份日志（13275 行，自 09-10 起）：

- 其中 **4931 行是 `fatal:` / `error:`**——从这台 ECS 拉 github.com 失败是常态
  （GnuTLS recv error、HTTP2 framing layer、443 连超时）。
- 日志里出现过的 HEAD 只有 **10 个**，而 `[ok] restarted` 记了 **4172 次**：绝大多数重启并不是
  因为有新提交。实测片段：00:19–02:54 一路反复 `[deploy] 85c2554… -> FETCH_HEAD`、
  `[deploy] b832856… -> FETCH_HEAD` 并重启服务，而 HEAD 自始至终没变。
- 结果就是**第九批 `ee7ac1a` 从未被部署过**（在整份日志里出现 0 次），线上一直停在第八批
  `b832856`。所以那句话不是「想当然的旧说法」，而是当时的事实。

**问题出在脚本守卫那三行**（`/usr/local/bin/literature-autodeploy.sh`）：

```bash
git fetch origin master -q 2>>"$LOG"
LOCAL=$(git rev-parse HEAD)
REMOTE=$(git rev-parse FETCH_HEAD)
[ -n "$LOCAL" ] && [ "$LOCAL" = "$REMOTE" ] && exit 0
```

它既不看 `git fetch` 的退出码，也不比对 `origin/master`，而是比对 `FETCH_HEAD`——那是 `git fetch`
的临时产物，拉取失败时会是空的或陈旧的（日志里 `[deploy] <sha> -> FETCH_HEAD` 的尾部、远端 sha
位置直接印出字面量 `FETCH_HEAD`，就是这么来的）。与 HEAD 不等，守卫被绕过，于是一次白重启。

**每次真正部署会重新处理那 4 本内置书**，约 1–3 分钟 CPU 忙、期间访问偏慢；所以上面这种
「拉取失败也照样重启」不只是日志难看，它让服务长期处在反复重启、反复重算的状态里。

**本次的处理。** 推送 `754e601` 之后，02:56 那一轮 cron 的 fetch 恰好成功，线上已自动更新：
服务器 HEAD 与 `origin/master` 同为 `754e601`，服务 active，公网
`http://39.96.194.197/visualization` 返回 200，且页面已带第九批的标记（`exportMoreBtn`、
`quickstart-lead` 等）——也就是说第八批、第九批现在才真正上线。

**还没做的：脚本本身没改。** 上面那三行守卫仍是原样，「拉取失败 → 白重启一次、且迟迟追不上
新提交」还会继续发生。修法是检查 fetch 退出码，并改成比对 `origin/master`；那是生产机上的
root 脚本，确认后再动，改动前会先备份原文件。

## 第十批：折叠区展开之后，层级还在（2026-09-28）

第九批把 6 个导出按钮分成「常用 2 个 + 收起来的 4 个」，方向是对的，但**一展开层级就没了**：
那 4 个低频按钮用的是和「导出图像」「复制此链接」一模一样的样式，7 个按钮长得一样，
而展开那一刻恰恰是最需要层级的时候。这一批补上展开态的层级，并顺手修掉三件确定是错的事。

### 1. 一条线，一句规则

`#copyLinkBtn` 与 `#exportMoreBtn` 之间加了一条 `.export-divider`（1px × 18px）。规则一句话说得完：
**线左边一律实心，线右边一律次要样式**——连切换钮自己也用次要样式，因为「更多导出」本身也是低频动作。
一条规则管到底，展开后层级不会消失。

次要样式是 `background: transparent` + `border-color: transparent` + `color: var(--ink-70)` + `font-weight: 500`。
**保留 1px 边框、只把颜色设透明**：写 `border: none` 会让盒子各边小 1px，两排按钮的边缘对不齐。
（中文 Windows 上 YaHei 没有 500 这一档，会落到 400，所以目标平台上实际看到的对比是 600→400。）

这里踩到两个**不报错的坑**，属于「特异性输了，但没有任何提示」那一类：
- `#exportMoreBtn` 同时命中 `.export-group button`（0,1,1）。单独写 `.export-more-toggle`（0,1,0）
  会被整个盖掉，四个属性一条都不生效。必须写 `.export-group .export-more-toggle`。
- `.export-more button` 与 `.export-group button` 同为 (0,1,1)，只靠源码顺序赢。写成
  `.export-group .export-more button` 就不再依赖顺序。

实测（1400px、展开态）：切换钮与 4 个低频按钮的 `backgroundColor` 全是 `rgba(0, 0, 0, 0)`、
`fontWeight` 是 `500`、`borderTopWidth` 仍是 `1px`；「导出图像」仍是 `rgb(253, 249, 239)` / `600`；
7 个按钮 `height` 都是 33，`top`/`bottom` 完全相同；分隔线 18px、垂直居中（偏移 7.5px）。

### 2. 箭头不再靠 JS 改文字（旧写法有两个 bug）

旧代码是 `this.textContent = willOpen ? '收起导出 ▴' : '更多导出 ▾'`，两个问题：

1. **同一个控件两个名字。** 读屏用户第一次听到「更多导出」，第二次回到同一个按钮听到「收起导出」。
   而且「收起导出」还 overclaim——它只收起 6 个导出里的 4 个。
2. `textContent =` 会把箭头那个节点整个删掉。

现在箭头是按钮里一个 `aria-hidden` 的 `<span class="export-caret">▾</span>`，**按钮文字永远不变**，
朝向由 CSS 按 `aria-expanded` 旋转：

```css
.export-caret { display: inline-block; font-size: 0.72em; transition: var(--transition-control); }
.export-more-toggle[aria-expanded="true"] .export-caret { transform: rotate(180deg); }
```

`display: inline-block` 不能省——inline 盒子不可 transform，旋转会静默失效。
朝向由 `aria-expanded` 决定而不是由 JS 改写，**可见状态与无障碍状态同源**，
不可能出现「读屏说已展开、箭头还是 ▾」。

实测：完整展开+收起一个来回之后，`#exportMoreBtn.textContent` 仍是 `更多导出 ▾`、`.export-caret`
仍在 DOM 里（旧写法这两条都会挂）；展开时 `transform` 是 `matrix(-1, 0, 0, -1, 0, 0)`、收起时是 `none`。

### 3. Escape 收起 + 焦点归位

Escape 监听挂在 **`.export-group`** 上，不挂 `document`：keydown 只会从组内有焦点的子元素冒泡上来，
「焦点在组内」这条前提是白拿的，于是**结构上**不可能抢走星系弹窗的同一个 Escape。
收起后显式把焦点还给切换钮——面板里的按钮会跟着一起 hidden，浏览器接着把焦点丢给 `<body>`。
不写 `preventDefault` / `stopPropagation`：Escape 在这条路径上没有浏览器默认行为，拦下来只会让别的监听者收不到。

实测：焦点在组内按 Escape → `hidden: true`、`aria-expanded: "false"`、
`document.activeElement.id === 'exportMoreBtn'`；焦点在组外（`#chartTypeSelect`）按 Escape → 面板纹丝不动。
Tab 顺序：收起时从切换钮直接跳到 `#chartTypeSelect`（跳过那 4 个）；展开后依次是
`exportSvgBtn` → `exportDataBtn` → `exportSummaryBtn` → `exportCiteBtn` → `#chartTypeSelect`
（顺带证明分隔线不参与 Tab）。

### 4. 不再靠 `display: contents`

`.export-more` 原来是 `display: contents`（全仓唯一一处），只为了让 4 个按钮成为父级 flex 的直接子项，
收起靠 `[hidden] { display: none !important }` 压过它。现在它是真容器：
`display: flex; flex-wrap: wrap; align-items: center; gap: 8px;`——4 个按钮自成一个 flex 项，
窄屏整体换行、不会散到两行，320px 下也不撑宽页面。

### 5. 窄屏那条线：实测之后决定撤掉（≤379px）

分隔线落在行尾时什么也没标。它该不该出现的条件**不是屏幕多宽，而是右边有没有东西**，CSS 判不了，
只能取实测的换行起点。逐档量下来：≥372px 时它与「更多导出」同排（7.5px 居中偏移）；≤368px 时被挤到
上一行末尾、跟「复制此链接」同排。取 **379px** 为界。代价是不对称的——多藏几像素只是少一道装饰
（层级由次要样式扛着，不靠这条线），少藏了就是在小屏上留一道看不懂的竖线，所以宁向往宽里取。

不用别的办法的理由：把线做成切换钮的 `border-left`，它会跟着换行跑到行首；做成绝对定位的伪元素，
它不参与换行也就永远画在那儿——两种都是在另一个位置重犯同一个错。

实测：320 / 360（含触屏、按钮 44px）`display: none`、页面无横向溢出；380 / 390 / 978 / 1400 为 `block`

## 第十一批：线上喂了一个月的旧数据（2026-10-07）

**先说结论：线上演示站 `http://39.96.194.197/visualization` 一直在用 9 月 3 日生成的旧管线数据，
而本仓库里的代码十天前就已经是新的。** 这让两个招牌功能在线上等于没有：

- **风格星系**拿不到共享投影模型，退化成「各书各自计算（点与点之间的距离不可直接比较）」
  ——也就是本工具最核心的卖点「跨书可比」，在线上是关掉的。
- **走势图**底部没有章节刻度，导出的 CSV「所在章节」一列**全空**。

本地打开是对的，只有线上坏——所以前面十批的实测全都在本地做，谁也没看见。

根因是**两个互不相干的原因叠在一起**：一个让旧数据永远留着，另一个让代码修复也上不去。

### 1. 根因一：`data/processed/` 不进版本库，而服务只看「文件在不在」

`data/processed/*.json` 在 `.gitignore` 里（第 15 行）。服务器上那份是部署当天生成的，此后
`git pull` 不会碰它。而 `_ensure_demo_data()`（`api_server.py`）的判断是：

```python
if target.exists():
    _demo_data_ready = True
    return True          # ← 只要文件在，就再也不看它一眼
```

文件一直在，于是它永远存在、也就永远不会被重算。**这不是「偶尔忘了重新部署」，是结构上的死角**：
将来管线再改一次，同样的坑会原样再踩一遍。

两边数据的实际差别（`curl` 线上 `/api/fingerprint-data` 直接读出来的）：

| | 线上（09-03 生成） | 本地 / 重算后 |
|---|---|---|
| `metadata` 字段 | `totalBlocks, totalWords, avgSentenceLength, avgSimpsonIndex` | `schemaVersion: 2, chapters, projection, blockSize/overlap/step, analyzedWords …` |
| 切块 | `totalBlocks: 22`、`totalWords: 220000`（无重叠的旧切法） | `102` 块，`blockSize 10000 / overlap 9000 / step 1000` |
| 章节 | 无 | 43 / 35 / 7 / 25 章 |
| 投影 | 无 | `mode: "shared"`，模型 `pca-4709af31caa3` |

### 2. 修法一：让服务自己认出「这份数据是旧的」

`api_server.py` 里新增 `_DEMO_SCHEMA_VERSION = 2` 与 `_demo_corpus_is_current()`：**只要有一本书带
`metadata.schemaVersion >= 2` 就算当前**（整个文件是一次写出的，不存在半新半旧）；读不动、
结构不认识，一律当过期。`_ensure_demo_data()` 于是改成「不存在**或**不是当前管线生成的」才重算，
并且重算后按新判定复核结果，而不是像原来那样只看 `target.exists()`。

另外加了一条**负缓存**：同一份旧文件只尝试重算一次（`_demo_repair_stamp` 记它的指纹）。重算要跑
1~3 分钟，万一失败（比如 `data/raw/` 是空的），不能让此后**每个请求**都卡满一次；文件被换过
（比如管理员手动拷了一份进来）则允许再试。

顺带把 `_corpus_stamp` 里那段 `try/except stat` 抽成 `_file_stamp` 复用，语义不变。

测试 **151 → 167 项**，全部走临时目录、不碰仓库里的 `data/`：
`_demo_corpus_is_current` 7 项（当前 / 更高版本 / 缺字段 / 更低版本 / 坏 JSON / 缺文件 / 各种畸形结构），
`_ensure_demo_data` 9 项（该重算的三种、不该重算的三种、失败不重试、文件换过可重试、生成抛异常不冒泡）。

### 3. 根因二：自动部署脚本每 2 分钟白重启一次服务

上一节（`2026-09-28` 那段）说过脚本守卫有 bug、但「还没做」。这次做了。

直读服务器上那份日志（我接手时 20262 行）：**`[ok] restarted` 记了 6362 次，
而 `ff merge failed` 是 0 次**。从 9 月 28 日到 10 月 7 日这 9 天里，HEAD 一次都没变过，
但服务每 2 分钟被重启一次——**一个需要 1~3 分钟 CPU 才能重算完 4 本书的服务，被无限重启了 9 天**。

守卫那三行（老脚本）：

```bash
git fetch origin master -q 2>>"$LOG"          # 不看退出码
LOCAL=$(git rev-parse HEAD)
REMOTE=$(git rev-parse FETCH_HEAD)            # 比的是 FETCH_HEAD，不是 origin/master
[ -n "$LOCAL" ] && [ "$LOCAL" = "$REMOTE" ] && exit 0
```

这台 ECS 拉 github.com 失败是常态（GnuTLS recv error、HTTP2 framing layer、443 连超时，
实测有一次卡满 **131 秒**）。拉取失败时 `FETCH_HEAD` 是**上一次成功拉取**的陈旧值
（彻底失败时 git 甚至会把 `FETCH_HEAD` 这个字面量打印出来），于是 `LOCAL != REMOTE` 恒成立，
守卫被绕过，每一轮 cron 都走一遍 merge + restart。

### 4. 修法二：一行判退出码，一行换比对对象

脚本现在收进了仓库（**`literature-autodeploy.sh`**，仓库根目录），服务器上那份是它的安装副本——
以前它只存在于生产机上，不在版本控制里，这也是这个 bug 能活这么久的原因之一。

```bash
if ! timeout 90 git fetch origin master -q 2>>"$LOG"; then
  exit 0                    # 拉不动就安静退出，下一轮自然会重试；绝不为这个去重启服务
fi
LOCAL=$(git rev-parse HEAD 2>/dev/null)
REMOTE=$(git rev-parse origin/master 2>/dev/null)
if [ -z "$LOCAL" ] || [ -z "$REMOTE" ]; then
  echo "…[error] cannot resolve HEAD or origin/master" >> "$LOG"; exit 0
fi
[ "$LOCAL" = "$REMOTE" ] && exit 0
…
if git merge --ff-only origin/master -q; then
```

`timeout 90` 是这次实测加的：不设上限，一次卡满 131 秒的 fetch 会把这一轮 cron 拖住、
并连带跳过下一轮。

**四种情形在本地用一整套桩（stub `git`/`systemctl`/`flock` + 真 git 建的小仓库）逐条跑过**，
被测脚本与仓库里这份**除 4 行路径外逐字相同**（`diff` 验过）：

| 情形 | 新脚本 | 旧脚本 |
|---|---|---|
| 拉取失败（线上最常见） | restarts=0、日志不增 | **restarts=1**（那 6362 次的来源） |
| 拉取成功、无新提交 | restarts=0 | restarts=0 |
| 拉取成功、有新提交 | restarts=1、HEAD 前进、工作区更新 | — |
| 有新提交但 ff 不可行 | restarts=0，记 `[error] ff merge failed` | — |

## 第十四批：开 gzip，以及让首屏那份 1.5 MB 能走 304（2026-10-07）

前面每一批都在改「页面长什么样」，这一批改的是**传输**——而且是这批之前从没量过的维度。
一量就发现首屏要传 **1.83 MB**，其中只有 HTML 被压过。

### 1. gzip：模板里那六行注释

`/etc/nginx/nginx.conf` 的 Gzip 段是发行版模板的原样：只有 `gzip on;` 生效，
`gzip_types` 整行还是注释。而 nginx **无条件压 `text/html`**，所以配完模板的人会看到
HTML 有 `Content-Encoding: gzip`、以为「gzip 已经开了」——它确实开着，只是只对 HTML 生效。

实测（同一台机器、同一份内容，`Accept-Encoding: gzip`）：

| 资源 | 改之前 | 改之后 | |
|---|---|---|---|
| `/visualization` | 28234 B | 24945 B | 本来就在压，级别 1→5 顺带小了 3 KB |
| `static/css/d3-style.css` | 56491 B | 17668 B | −69% |
| `static/js/d3-charts.js` | 170004 B | 57448 B | −66% |
| `/api/fingerprint-data` | **1570530 B** | **512897 B** | −67% |
| **首屏合计** | **1.83 MB** | **约 599 KB** | **−67%** |

改的就是那六行，另外补了三条：

```nginx
gzip_vary on;          # 让中间缓存按 Accept-Encoding 分开存，免得把 gz 内容发给不支持的客户端
gzip_proxied any;      # 本站响应全部来自 proxy_pass，不写这条反代出来的响应不会被压
gzip_comp_level 5;     # 默认是 1；对 JSON 而言 5 的收益远大于代价，再往上就很小了
gzip_min_length 1024;  # 太短的响应压了反而更大
gzip_types
    text/plain
    text/css
    text/xml
    text/javascript           # ← 注意不是 application/javascript
    application/javascript
    application/json          # ← /api/fingerprint-data 靠这条
    application/xml
    application/xml+rss
    image/svg+xml;
```

**`text/javascript` 这一条是这批最容易写漏的地方**：模板注释里给的是 `application/javascript`，
照抄的话 `.js` 不会被压——因为 **Python 3.13 的 `mimetypes` 给 `.js` 发的是 `text/javascript`**，
而 nginx 的 `gzip_types` 是按上游给的 `Content-Type` 精确匹配的。改之前的实测响应头就是
`Content-Type: text/javascript; charset=utf-8`。两个都留着，换 Python 版本也不会失效。

压缩**没有改动内容**：四个资源都逐字节比对过「解压后的 body」与「不声明 gzip 时拿到的 body」，
md5 完全一致。（第一版比对脚本我写错了——把 `--compressed` 和显式 `-H 'Accept-Encoding: identity'`
同时给 curl，后者覆盖了前者，于是两边根本不是同一件事。记在这里，免得下次又「验出」一个假故障。）

### 2. 另一半：`/api/fingerprint-data` 每次首屏都要拉，却从不带缓存头

gzip 之后它仍有 513 KB，而且**每一次打开页面都要重下一遍**——它一直是个不带任何
缓存头的 200。加上 ETag 之后：

```python
etag = _corpus_etag()          # = sha1(repr(_corpus_cache["key"]))
if etag is None:
    return resp
resp.set_etag(etag)
resp.headers["Cache-Control"] = "no-cache"
return resp.make_conditional(request)
```

指纹直接复用 `_load_corpus` 判断「要不要重读文件」用的那个 key（`all_books.json` 的
mtime + 大小 + 整个书库的指纹）。**这样「数据变了」和「ETag 变了」是同一件事，
不可能脱节**：重新生成数据会变、用户上传/删除一本书也会变。

`no-cache` 容易被误读成「不许存」，它其实是「**可以存，但每次都要先确认**」——这正是我们要的：
数据确实会变，所以必须 revalidate；而 revalidate 的代价是一个 304。

实测（CDP，同一个浏览器、冷启之后按一次刷新）：

| | 第 1 次访问 | 第 2 次访问 |
|---|---|---|
| `d3-style.css` | 17968 B | **300 B**（304） |
| `d3-charts.js` | 57748 B | **300 B**（304） |
| `fingerprint-data` | 513197 B | **300 B**（304，`decodedBodySize` 仍是 1570530，即从缓存取的） |
| **合计** | **约 589 KB** | **900 B** |

也没有把 304 弄坏在代理上：nginx 对压缩过的 200 会把 ETag 变弱记成 `W/"…"`，
带着这个值回来仍然是 `304 NOT MODIFIED`；声明 `Accept-Encoding: identity` 的客户端同样能 304。
`Vary: Accept-Encoding` 两条路径都在。

  每换一本书、换一次指标都会把「复制 按钮」重念一遍。
- `.insight-copy` 要**显式写 `transform: none; box-shadow: none;`**——全局 `button:hover` 带
  `translateY(-1px)` 和投影，一个 12px 的小控件悬停时跳起来很难看（第六批给 `.sort-control`
  抹过一次同样的东西）。

实测复制出来的是这样（框选之后）：

```text

下面这些数字只统计走势图上框选的 50.0%–100.0% 区段，不是全书。

注意最后那句「说明」是**必须跟着走的**：异常片段一旦离开页面，旁边就再没有东西提醒
「偏离 ≠ 写得好或不好」。

### 3. 摘要从 `.md` 改成 `.txt`

`文印_分析摘要_*.md` → `文印_分析摘要_*.txt`，`text/markdown` → `text/plain`。
三处 Markdown 记号换掉：文件头下面一条 `═` 横线、`## 书名` → `【书名】`、`> 说明：…` → `说明：…`。

理由：这份摘要的读者是文科研究者，打开它的是记事本、Word、或 Word 的「插入 → 文件」；
满屏 `#` 和 `>` 在那些地方是噪音，不是格式。列表符号 `-` 留着——纯文本里它一样好读。
顺带 `exportSummary()` 里自己复制粘贴的那十行 blob/link 代码换成了现成的 `downloadBlob()`。

结论区放在**每本书的明细前面**，因为它是结论、不是附录。

### 4. 引用条目：原来把「文印」写成了《白牙》的作者

旧的 `.bib` 只有一条 `@misc`：`author = {{文印（文学指纹分析工具）}}`、
`title = {文印·文学指纹分析：{白牙}}`。学生整段贴进参考文献，得到的就是「引用《白牙》，作者是文印」——
**原著反而没有条目**。现在分成两类，`.bib` 开头用几行纯文字讲清楚
（BibTeX 会忽略条目之外的内容，不需要 `@comment`）：

- **`@book`**：4 本内置书各一条，`author` / `title` / `year` / `publisher = {Project Gutenberg}` / `url`。
  元数据取自 `data/raw/*.txt` 开头那段 Gutenberg 头部（`Title` / `Author` / `Release date` / `eBook #`），
  不是凭记忆写的——Twain 1876 / Twain 1884 / London 1903 / London 1906，eBook #74 / #76 / #215 / #910。
  **`year` 是作品首次出版的年份**，电子版的发布日期写在 `note` 里；「两者别混」这句话也写进了 `.bib` 开头。
  查表按「去空格 + 小写」比对：书单的兜底文案里把 `The call of the wild` 写成了 `The Call of the Wild`，
  大小写不该让一条原著条目凭空消失。
- **`@misc`**：本次分析记录本身，`title` 改成「文印·文学指纹分析记录：…」，
  `note` 末尾加一句「原著条目见本文件开头的 @book」。
- **用户上传的书不发 `@book`**：上传的文件里读不到作者与版本，替你编一个比空着更糟。
  改为在文件里点名：「注：《X》是你上传的文本，本文件没有它的原著条目——上传的文件里读不到作者与
  版本，替你编一个比空着更糟。请按手上的版本自行补全。」

`@misc` 的字段顺序、末尾不留逗号这些老规矩都没动（BibTeX 靠逗号分字段，漏一个会整条报错、
丢掉除标题外的全部字段）。

### 5. 分享链接以前会静默少几本书

`buildStateUrl()` 只把书名写进 `?books=`。内置书在别人的服务器上也有，自己上传的那几本没有——

分享的是完整结果。现在 `copyShareLink()` 先比一下 `builtinBookNames`，选中了上传的书就做两件事：

- 按钮反馈改成「✓ 链接已复制（不含你上传的 1 本）」；
- 在全局状态条上点名哪几本、为什么、以及该改用哪条路：
  「链接里没有《X》：这是你自己上传的文本，只存在这台电脑上，别人打开链接时看不到。
  想把完整结果分享出去，请用「更多导出 → 导出摘要」。」

`builtinBookNames` 还没建好（书单还在加载）时不做判断，免得把所有书都当成上传的。

### 6. 文案：段落 → 片段（4 处）

界面上绝大多数地方叫「片段」，另有 4 处叫「段落」而指的是同一个东西——一个片段约 10,000 词，
远不止一段，叫「段落」是**量级上的错**。改掉的是：`选择书籍 · 拖选段落`、`拖拽选择段落`、
框选区的 `aria-label="段落范围选择框…"`、详情卡的 `aria-label="收起《X》的段落详情…"`。
实测三个页签的 `body.innerText` 里「段落」都已经是 `-1`。

### 7. 「观察角度」这个名字**不用改**（立项时列了，开工后撤销）

立项时它是一条待办：那个下拉改的是指标，在风格星系里却只改圆点大小、位置恒为功能词坐标
（`initStyleGalaxy` 里 `positionData` 永远取 `functionWords`），名字叫「观察角度」会让人以为它改的是位置。

开工前 grep 到 `updateGalaxySizeHint()`（`d3-charts.js:2141`）**已经在做这件事**：图例那行会随指标

## 🔧 变更记录：不让结论写错（2026-10-07，第十六批）

这一批不动任何算法，只动**说法**。专门查了一个维度：页面上那些把统计量翻译成人话的句子，
有没有哪句在统计上其实不成立。查出七处，全是「读起来像结论、实际推不出来」或者
「把范围说错了」，而目标读者是会把结论直接抄进论文的文学研究者。

### 1. 框选时说「整体句子最长」——同一块面板里自己打自己

`#insight-content` 的第一行在框选生效时写「下面这些数字只统计走势图上框选的 50.0%–100.0% 区段，
**不是全书**」，紧接着第二行却是 `INSIGHT_METRIC` 里写死的「**整体**句子最长」。两句话相隔一行、
互相否定；而 `currentMean` 那时报的本来就是区段均值，所以错的是措辞、不是数。第十五批的 README
示例（见 §11）里这两句正是并排出现的，当时没被看出来。

改法：`high` / `low` 两个词里**不写范围词**（`整体句子最长` → `句子最长`），范围统一由拼句子时的
一个 `scopeWord` 加（框选时「在框选的 X 区段里」，否则「整体」）。于是框选态下**结构上**不可能
再说出「整体」——不是靠记得改，是那个词根本不在表里。

顺带补「在所选 N 本中」：「最长 / 最短」是在用户勾的那几本里排出来的，不加限定会被读成
「A 是所有作家里句子最长的」。

### 2. 「值得一看的片段」最多列 8 条，却说成全集

`detect_anomalies(values, z_threshold=2.0, max_items=8)` 排序后截断到 8 条（`src/analysis_utils.py`），
而面板标题、正文、脚注、导出物里**没有一个字**说明这只是前 8 个。读者会写出「本书共 8 个偏离片段」，
实际可能有 20 个。接口本来就返回了 `anomalyCounts`，前端一次都没引用过。

改法：`counts` 里多报一个 `total`（`len(scored)`，两种口径都算上、去重前）——**只多带一个数，
不参与任何计算，判定逻辑一个字没动**。前端 `anomalyNotes()` 在 `total > items.length` 时多说一句
「本书共找出 N 个偏离片段，这里按偏离程度只列出最靠前的 N 个」。`max_items=8` 本身保持不变。

### 3. 相邻片段重叠 9000 词，面板却把 ±2σ 当成稀有

片段是 `block_size=10000 / overlap=9000` 的滑窗切出来的，**相邻两条共享九成原文**。在这样的
近重复序列上算标准差，「离均值超过 2 个标准差」就不再是它字面上给人的那个「罕见」。CSV 导出的
注释里早就承认过这一点，唯独最像结论的这块面板没承认。

改法：脚注补一句「这次统计基于本书的 N 个片段，相邻片段之间重叠约 9000 词、并不是互相独立的样本，
所以它只适合用来挑原文，不构成显著性结论」。片段数取接口返回的 `totalBlocks`；重叠词数走
`normalizeBookMeta()`（旧数据没写 `overlap` 字段，它会按「窗口长 − 步长」推出来），推不出来
就退成「有大段重叠」，不硬编一个数糊上去。

### 4. 「取不到」被当成了「没有」

`renderAnomalies()` 在服务端返回非 success 时原来只做 `panel.innerHTML = ''`，`.catch()` 里写着
「拿不到就不占地方，不打扰用户」。可是服务端在这条路上写了一句很具体的话——「有效的片段太少，
做不了异常分析。」——**整句被丢掉了**。于是用户先看到「正在找这本书里偏离较大的片段…」，
然后它凭空消失，分不清是「这本书没有偏离」还是「压根没算成」；更要紧的是缓存同时被清空，
**导出的摘要与「复制结论」里整段【值得一看的片段】被无声略过**，读的人只会以为这本书没问题。

改法：两个失败分支都改成把原因显示在面板里（服务端那句原样用，网络失败给一句通用的），
并写进 `lastAnomalyReport`（带 `failed: true` 和 `reason`）；`buildAnomalyText()` 对 `failed`
的记录输出「这一节这次没有生成：<原因>」。

> **更正一句我自己排查时说的话。** 这一条我起初写成「把『算不了』说成『比较均匀』」，
> **那是我说错了**：接口在 `api_server.py` 里早就有「有效片段少于 5 个就返回 404」的守卫，
> 所以「整体比较均匀」只在真的没有偏离片段时才出现，那句话本身是对的。真正的问题是 404 里
> 那句写得很准的话被前端丢掉了。

### 5. 「中后段句子越写越长」——把两个半段的均值之差说成了趋势

`trend` 的定义是**后半段均值 − 前半段均值**（`getAdvComputed`），表里却写「中后段句子**越写越长**」：
既暗示了单调趋势（后半段里一个尖峰就能把半段均值抬起来，而全书未必在变），位置词也错
（比的是前半段与后半段，不含「中段」）。

改法：四个指标的 `up` / `down` 全部改成「后半段的 X 高于 / 低于前半段」，输出那行同时给出差值
并点明性质——「（前后半段均值相差 4.04，不代表全书单调变化）」。

功能词那一对单独说：它的值是功能词 PCA 的**第一主成分坐标（有符号）**，原话「持续偏移 / 趋于回归」
在数学上推不出来（坐标更靠正侧 ≠ 离均值更远），所以只描述「偏向坐标轴的一端 / 另一端」。

### 6. 「起伏最小，风格最平稳」

两处收窄：

1. `currentStd` 只是**当前这一个指标**的起伏（观察角度是平均句长时就只是句长），撑不起「风格」
   二字——同一本书完全可能句长最稳、用词重复度起伏最大。改成「《X》的「平均句长」起伏最小
   （只就这一个指标而言）」，并补上「在所选的书里」。
2. `d3.deviation` 对单元素数组返回 `undefined`，代码用 `|| 0` 兜底，于是一本只有 1 个片段的书
   标准差恒为 0、**必然夺冠**——不是它稳，是它没数据。加了样本门槛（`activeSegment.length >= 5`
   且 `currentStd > 0`），不合格就不说这一句。

### 7. 星系里「因写作风格相近而聚集在一起」

星系的坐标是**高频小词用法的 PCA 二维投影**，「因…而」把描述性的邻近说成了因果，还把
「高频小词用法」升格成「写作风格」。同一页顶部的说明自己写的是「点与点靠得近，只说明高频词的
用法相近」。改成与它一致：**「挨得近只说明高频小词的用法相近，不代表内容或水平相似。」**

### 8. 方法说明里的文本来源（同一类错，顺手）

导出的方法说明原来写「文本**经 Project Gutenberg 页眉页脚清理**与常见缩写还原后」。
`clean_text()` 对每一本书都跑，但只有真带 Gutenberg 页眉页脚的文件才被剥掉那一层——对用户上传的
其它来源文本，这句话是**假话**，会让读者以为该文本确实带着（并被清理了）Gutenberg 页眉。

改成：「文本统一空白、还原常见缩写；若来自 Project Gutenberg，另清理其页眉页脚
（其它来源的文本原样保留，没有这层清理）。」

### 9. 屏幕与导出共用同一段话

新加的 `anomalyNotes(report)` 放在 `d3-charts.js` 里，面板脚注与 `buildAnomalyText()` 都调它，
所以「有上限」「看样本量」「不是独立样本」这三句在**屏幕、导出摘要、「复制结论」三处逐字相同**。
第十一批和第十五批都在「两处各说一套」上吃过亏，这次让它们只剩一个来源。

### 1. 600 个片段 = 正好撞上超时线，而只有一个 worker

线上是 `gunicorn api_server:app --bind 127.0.0.1:8000 --timeout 180 --workers 1`。
`MAX_BLOCKS` 原来是 600，而服务器上每块的真实成本约 **0.30 秒**（本文件记过一次：
`generate_data.py` 实测 248 块跑了 75 秒，75 ÷ 248 = 0.302）。于是：

```
600 × 0.30 ≈ 181 秒  >  --timeout 180
```

也就是说，**恰好等于上限**的那次上传会跑满 180 秒、被 gunicorn `SIGKILL`，上传者拿到 502；
而 `--workers 1` 意味着**这三分钟里整站没有任何人在应答**——不是「这个人慢」，是「所有人都打不开」。

改法只有一个方向：**把上限降到超时预算的一半**。`MAX_BLOCKS = 600 → 300`，300 × 0.30 ≈ 91 秒，
留了一倍余量。

> **这是一次真实的降级，写清楚代价**：300 个片段覆盖约 30.9 万英文单词
> （`(300-1) × (10000-9000) + 10000 = 309000`），装不下《战争与和平》（英文译本约 56 万词）这类
> 超长篇——原上限 600 块也装不下它，但比现在宽一倍。换句话说，**能在一次上传里分析的最长文本
> 缩短了一半**。换来的是「一篇长文不会再把全站拖死」。超长篇的出路写在报错里：拆文件分次上传、
> 或先截取要研究的章节。

没有选「把 `--timeout` 调大」这条路，两个原因：一是**把 180 改成 300 只是把悬崖挪远，同时把
「整站不可用」从 3 分钟拉长到 5 分钟**——`--workers 1` 的病根是「一个长请求独占唯一的 worker」，
调超时治不了；二是这条 `--timeout` 写在 systemd 单元里，**单元不在本仓库**（`Dockerfile` 里那份
是给镜像用的），改不动。

报错文案是 f-string，跟着常量走，现在自动变成：

> 文本太长，单次最多分析约 300 个片段（覆盖约 30 万英文单词），这份文本约 N 个片段。请拆分文件后分次上传，或先截取要研究的那些章节。

### 2. 「值得一看的片段」只分析第一本书（欠了两个批次）

`renderAnomalies(data)` 里取的是 `data[0].name`——**同屏选了多本书，屏幕上和导出里都只有第一本的
偏离片段**。而同一块面板上面的「一句话解读」早就逐本遍历了，两块结论口径不一致：
左边说「这几本书怎么样」，右边只摆得出一本书的证据。

> 这条是**第十七批 §9** 自己记下的「本批没做的」，理由写得没错——要动 `lastAnomalyReport` 的结构，
> 连带改导出摘要与「复制结论」。这一批把它做了。

改法：

- `lastAnomalyReport`（单个对象）→ **`lastAnomalyReports`（数组）+ `lastAnomalyBooks`（同序书名表）**。
  顺序与「全书对比」页当前选中的书一致；某本书的请求还没回来时，那一格是 `null`。
- `renderAnomalies()` 逐本各发一次 `/api/analysis`。**代数**（`anomalyRequestId`）在一次渲染里
  递增一次，同一代里的每个请求各自校验，切书/切指标时整批作废——不再靠「一个请求号 + 只发一个请求」。
- 新增 `renderAnomalyPanel()` / `anomalyBlock(report, entry)`：**每本书的请求回来一次就重绘一次**，
  先回来的先显示，不必等最慢的那本。还没回来的那本显示「正在找《书名》里偏离较大的片段…」。

  换了第二本书而第一本没动，会被当成「算过了」直接返回，第二本书永远停在旧数据上。
- 脚注（`anomalyNotes`）**按书各写一份**——「本书共 63 个片段」这种话一张嘴只能对一个统计对象说。
  屏幕与导出照旧共用同一个函数，不可能各说一套。
- `buildAnomalyText()` 拆成 `buildAnomalyText()`（遍历数组、段与段之间空一行）+ `anomalyTextForReport(report)`
  （原来那一份逐字未改）。**只选一本书时，屏幕文本与导出文本与改动前逐字节相同。**

实测（1400×900，CDP）：

  中间正好一个空行。

### 3. 性能：七处「用起来卡」

| 位置 | 原来 | 现在 |
|---|---|---|
| `_copySources`（复制按钮的文本池） | `push` 后永不清理，长会话（研究者常一开几小时）只增不减 | `registerCopySource()` 用 `Map` 去重，同一段文字只存一份 |
| 平滑滑块（`#smoothness`） | `input` 事件每拖一格就整张 `initChart()` 重建 | 用 `requestAnimationFrame` 合并到每帧最多一次；`syncUrlState()` 仍每次同步 |
| 看板的 `getAdvComputed()` | 一次 `updateAdvCharts()` 里被完整重算 3 遍 | 算一次，把结果传给 `updateHighlightVisuals(data)` / `updateDrillPanel(data)` |
| 折线图图例高度 | 画布写死 400、行距 25 → **第 15 本起书名掉到 `viewBox` 外**，图上有线、图例里找不到它叫什么 | 画布按图例行数撑高，**绘图区高度不变**（书多书少曲线形状一致） |
| 提示框 `showTooltip` | 每次悬停新建 `div`、量一次 `getBoundingClientRect`（强制同步布局），`hideTooltip` 再删掉 | **全程只建一个** `div`，反复复用；隐藏只淡出、不删节点（`.tooltip` 本来就是 `pointer-events:none`） |
| 星系 hover 的邻域判断 | `neighbors.includes(node)` 是数组线性查找，邻居多时退化成 O(n²) | 先建 `Set`，`neighborSet.has(node)` |
| 异常面板的重复请求 | 键盘框选每按一次方向键都重发一次 `/api/analysis` | 见 §2 的去重键；同一「书 + 角度 + 有无框选」直接复用 |

> **关于「星系 hover 是 O(n²)」这条**：第十七批 §9 把它列进了待办。核查下来它**不成立**——
> 邻域检查是 hover 时一次的 `filter`，布局走 `d3.forceSimulation`（自带四叉树）。这一批顺手把
> 那个 `includes` 换成 `Set`（上面那一行），但**不是因为原先会卡**，是因为它本来就是线性查找。

实测：

  `mouseout` 之后 **节点仍在、`opacity 0`**（不再删了）。

### 4. 无障碍：五处

1. **英文原文没有 `lang="en"`。** 全页唯一的 `lang` 是 `<html lang="zh-CN">`，语料却是英文小说：
   读屏用中文音库逐字念英文原文和关键词，盲人研究者听到的是不可辨认的音节。给这些块补上
   `lang="en"`：提示框关键词、`.keyword-tag`、片段详情里的原文、弹窗关键词、`#modal-long-text`
   （**只有真有摘录时才加**，否则 `removeAttribute`——空容器挂着 `lang="en"` 没意义）、`.hud-tag`。
2. **折线只靠颜色区分书。** `BOOK_COLOR_RANGE` 里同时有砖红 `#b5472f` 和灰绿 `#6b8f5a`，
   红绿色盲读者对不上书名。加了**第二编码通道**：`BOOK_DASH_RANGE`（实线 / `10 5` / `2 4` /
   `14 4 3 4` …），**槽位与颜色同源**（`bookSlot()`），所以不可能出现「颜色指这本书、线型指那本书」。
   屏幕上的图例从 15×15 的色块换成 **16px 的短线**（线型一并画出来），「全书对比」页的**导出图例**
   也把 `stroke-dasharray` 带走了——否则导出物等于把屏幕上唯一那条「不靠颜色也能分辨」的线索丢在页面里。
3. **一次加载同时写两个 live region。** `showLoading` / `showError` 既写顶部状态条
   （`role="status"`），又写详情卡（`role="status"`），读屏把几乎同一句话念两遍。给**详情卡**
   那两张状态卡加 `aria-hidden="true"`：读屏只听状态条那一份，眼睛两份都看得见。
   判定规则写在注释里——只在「状态条那句话活得和卡片一样久」时才隐藏（`setGlobalStatus` 只对
   `success`/`notice` 自动 6 秒后消失，`loading`/`error` 是常驻的）。
4. **键盘框选把「一句话解读」念十遍。** 方向键每按一次都会走 `advBrushed → updateAdvCharts → renderInsight`，
   而 `#insight-content`/`#anomaly-content` 都是 `aria-live="polite"`：按住方向键，读屏把整段解读
   一次次排进播报队列，按十下念十遍，松手之后还在念。新增 `beginQuietConclusions()`：键盘框选期间
   把这两块设成 `aria-live="off"`（改写内容不播报），**停手 900ms 后**开回 `polite` 并补播一句短的
   （「已框选 45.8%–56.4% 区段，页面上这些结论都只统计这一段。」）。**只有键盘这条路静音**——
   鼠标框选要松手才触发一次，那一次本来就该播。
5. **`<label>` 没连上滑块。** 「曲线平滑：」那个 `label` 没有 `for`，点它不会把焦点给滑块，
   读屏也读不出绑定关系。补 `for="smoothness"`。

实测：

- 框选键盘：连按两次方向键的**当帧**，`#insight-content` 与 `#anomaly-content` 的 `aria-live`
  都是 `off`；**1300ms 后**都回到 `polite`，且 `#adv-drill-announce` 里有那句「已框选 … 区段…」。
- `label[for="smoothness"]` 存在。
- 「全书对比」页 3 本 → `collectExportLegend()` 的 `shape` 是 `line`，三条各自带
  `dash` = `10 5` / `2 4` / `14 4 3 4`；整张 SVG 序列化后含 `stroke-dasharray`。

### 5. 文本雨：两个真 bug

- **窗口缩放后列数不跟着变。** 雨滴数组只在初始化时按 `innerWidth` 铺一次，缩窗后画布变宽，
  右边那一大片永远没有雨。改成挂一个存下来的 `resize` 处理器：按新宽度增减 `drops`
  （多了 `push`、少了截断），初始化与 resize 共用同一个 `makeDrop()`。

  用户又点「开始」，那个待执行的清除会落在**新的** `interval` 上把它 `clearInterval` 掉——
  按钮显示「■ 停止文本雨」、画面上却一动不动。把计时器存进 `matrixStopTimer`，重新开始时先撤掉它。

实测：`toggleMatrixRain()` 关 → 200ms 后再开 → **再过 1400ms** 检查：
`isMatrixOn=true`、`matrixInterval !== null`、`matrixStopTimer === null`、`matrixResizeHandler` 已挂上
——雨在跑，没被冻住。（旧写法这三项会读出「在跑的状态 + 被清掉的 interval」。）

## 🔧 变更记录：每人一个独立书架（2026-10-08，第十九批）

这一批的主体是**把「我的图书馆」从一份共享目录改成每个浏览器一格**。捎带三件早已记下的小事：
上传上限的文案自相矛盾、`.dockerignore` 漏两个目录、自动部署脚本每次拉代码都失败。
指标算法、中文分词、文本雨里的 `Math.random()`、`src/` 与 `data/processed/` 一行未动。

### 1. 共享书库的伤害，不只是「书单混在一起」

在这之前，`data/library/` 是全站一份：**任何访客勾了「存入我的图书馆」，所有人都会在书单里看到那本书。**
比「多出一本书」严重的是下面三条，都是这一批之前真实存在的：

- **别人的原文会出现在你的屏幕上。** 保存时连每块 1200 字的原文预览一起落盘，而保存下来的书会并进
  所有人共用的那份语料——于是「值得一看的片段」「一句话解读」里会摘出**别人上传文本的原文**。
- **你什么都没传，风格星系图却多出几个点**（保存的书是那份语料的一部分）。
- **老师来评分时，看到的是全班一起上传的结果**，分不清哪些是自己写的分析。

### 2. 办法：每个浏览器一格，匿名编号，不做账号

站点是 HTTP、项目没有数据库，为一次性动作引入注册/登录/改密码/会话，收益为零、风险最大。所以：

- 每个浏览器发一枚**匿名编号**，存在 cookie 里（`HttpOnly`、`SameSite=Lax`、有效期一年；
  站点是 HTTP，`Secure` 设不了）。不注册、不登录、不收集任何个人信息。
- 编号只做一件事：在服务器上给你的书分一格目录（`data/library/<编号>/`）。
- **别人的书既看不见、也删不掉。** 书单里没有它、按名字取它的数据是 404、删它也是 404——
  「不在你的书架里」这一件事同时管住了三处，不需要三套判断。
- **删除令牌照旧是第二道锁**（第十一批那套机制原样保留）：编号决定「这本书是谁的」，
  令牌决定「你配不配删」。两者都对才删得掉。
- 编号是**浏览器自己写的**，所以服务端拿到它先做格式校验（16–64 位的字母/数字/`-`/`_`），
  通过了才拿去拼路径。伪造的值一律作废、换发新的。

> **必须说清的代价：清除浏览器数据（或换一台电脑、换一个浏览器）＝ 书架没了。**
> 书还在服务器上，但浏览器不再带着那枚编号去认领，书单里就只剩内置的 4 本。
> 想拿回来：把 `data/library/<旧编号>/` 里的 `.json` 挪进新编号的目录，或者用本地版重传一次。
> 这一条同时写进了页面上的勾选框说明——那是全页唯一解释「书存在哪」的地方：
> 「只有这个浏览器能看到（清除浏览器数据或换台设备就找不回来了）」。

### 3. 上传上限：三个数字，原来报的是错的那个

事实是三个不同的上限，谁先撞上取决于你在哪种部署里：

| 上限 | 值 | 谁会被它拦下 |
|---|---|---|
| nginx（线上才有） | 20 MB | 上传体积大的文件，请求**根本到不了应用** |
| 应用 `MAX_CONTENT_LENGTH` | 50 MB | 本地直跑时的兜底 |
| `MAX_BLOCKS`（第十八批降到 300） | 约 1.9 MB 正文 | **绝大多数人真正撞上的就是这一条** |

而前端原来对一切「太大」都回答「单个文件不能超过 50 MB」——数字错，原因也错。现在：

- 服务端自己写的解释**不再被前端那句硬编码顶掉**（判断顺序反了，先认 413 就直接返回那句话）；
- 拿不到服务端解释时（nginx 直接回了一张 HTML 错误页），兜底句**不报任何数字**：
  「文件太大，服务器不接受这么大的上传。请先截取要研究的章节，或拆成几个文件分次上传。」
- 上传框旁边的提示补上真正的上限感：「支持英文 .txt，建议 1 万词以上；超长篇（几十万词）请分次上传。」

顺带修掉一句**在线上是反的**文案：上传框那句静态兜底原来写死「分析只在本机进行，不上传服务器」——
那是本地版的隐私说明。静态文案不知道自己在哪种部署里，现在只留部署无关的长度提示，
隐私那句照旧由页面按环境现给（本机版说本机、线上说「会发到服务器分析、未加密传输」）。

### 4. `.dockerignore` 补上 `data/library/` 与 `.claude/`

`*.pdf` 本来就在，结课报告进不了镜像；这两个目录 `.gitignore` 里早就有，只有 Docker 漏了。
补上之后，本地真有一书库书时手动 `docker build` 也不会把它打进镜像。

### 5. 自动部署脚本：`git fetch` 显式走 HTTP/1.1

第十八批部署那天查过线上日志：cron 里的拉取失败几乎全是

```
error: RPC failed; curl 16 Error in the HTTP2 framing layer
fatal: expected flush after ref listing
```

这不是「慢」，是**秒失败**——跟脚本里已有的 `timeout 90` 不是一回事，两条都得在。
手动加 `-c http.version=HTTP/1.1` 实测**第一次就拉下来了**，所以仓库根目录那份
`literature-autodeploy.sh` 的 fetch 加上了这个开关。

> **服务器上那份还没换。** 换法见第十一批那节：`cp` 到临时文件再 `mv`，
> **不要**用 `install` 直接覆盖正在运行的 bash 脚本（它按字节偏移续读，会执行到新内容）。

### 6. 旧的顶层文件：不删、不搬、不写迁移代码

`data/library/*.json`（第十九批之前存在顶层的那几个）**不删除、不搬动**，只是不再出现在任何人的书单里。
线上那份实测是空的（0 个文件），所以生产上这件事不存在。**不写启动时自动搬迁**：
那会在 import 阶段动到开发者真实的 `data/library/`，而测试明确承诺过「绝不触碰仓库内的 data/」。

第十九批把代价写得很诚实：「清除浏览器数据或换台设备就找不回来了」。诚实，但只给了结论——
书还在服务器上，丢的只是那枚编号。这一批把编号**摆出来**：

- 切过去之后**连删除权限一起交回**——只给编号的话，找回后能看不能删，✕ 会回一句

  交回令牌不扩大实际暴露面，只是把「找回」补完整。
- 页面上照实写清代价：**拿到这个编号的人，都能看到这个书架里的书**，只在自己信得过的设备之间传。
  勾选框原来的说明也跟着改了：从「清除浏览器数据或换台设备就找不回来了」改成
  「……书还在服务器上，用「书架编号」可以找回」。

### 4. 认领一个编号：四道闸，任何一步失败都不动当前身份

这是本项目第一条「用户输入的字符串 → 身份」的入口（此前只有 cookie 这一条路），所以顺序写死了：

| 顺序 | 闸 | 不做会怎样 |
|---|---|---|
| 1 | 必须带自定义请求头 `X-Shelf-Claim: 1`，否则 403 | 防「登录型 CSRF」：跨站的普通表单也能让浏览器接受响应里的 `Set-Cookie`，被诱导的人此后上传的书会直接落进别人的书架 |
| 2 | 编号格式校验（16–64 位的字母/数字/`-`/`_`），不合法 400 | 编号是浏览器自己写的，通过了才拿去拼路径 |
| 3 | 限流（**单独一个桶**，不跟上传抢额度），太频繁 429 | 再往前就是「拿编号试运气」了 |
| 4 | 目标书架不存在**或目录是空的**，一律 404 | 两者同待遇；**任何失败路径都不建目录**——否则随机编号就能在服务器上刷出一地空目录 |

认领成功才改身份（cookie 属性仍由 `after_request` 那一处统一下发，不复制第二份），响应带
`Cache-Control: no-store`：认领成功后是整页刷新，只要浏览器拿了一次启发式缓存，刷新后页面会显示
**上一个**编号和上一个书单，看起来像没切成功——而且是间歇性的、极难查。切换前还会把地址栏里的
`?books=` 清掉：那是上一格书架的书写，留着会撞上一句「链接里的这 N 本书在这台服务器上找不到」的
假警报。

### 5. 删除令牌按编号分格存

令牌以前是一张平铺表（`{书名: 令牌}`）。换过书架之后，两格书架里可能有同名的书、令牌却不同，
平铺表会给出错的那一枚（403，而且无法自愈）。现在值形状升级为 `{"<编号>": {"<书名>": "<令牌>"}}`：

- **写**：只写进当前编号那一格。
- **读**：先查当前编号那一格，查不到再回退到旧的平铺形状——**老浏览器不清数据也不会丢删除能力**，
  靠这个读回退完成迁移，不写迁移代码。

### 6. 自动部署脚本：日志轮转 + 失败可诊断 + 重启后验活

第十八、十九批记账时留下的三处，这一批做完（仓库根目录那份 `literature-autodeploy.sh`）：

- **日志轮转**：`LOG` 超过 1 MB 就滚成 `.1`（只留一代）。放在任何写日志的动作之前，否则本轮
  还在往要滚走的那个文件里写。正常一轮 cron 只写 0–2 行，1 MB 够放几个月——这个文件大只可能是出事了。
- **ff 失败可诊断、但不刷屏**：抓住 `git merge --ff-only` 的 stderr，记下 `$LOCAL -> $REMOTE`、
  折成一行的 stderr（截 400 字符）、`git status --porcelain` 前 5 行。**同一个 REMOTE 只记一次**
  （状态写在 `/run/literature-autodeploy.lastfail`，成功时删掉）——cron 每 2 分钟一轮，不设这道闸
  就是文件头那 6362 次刷屏的翻版，只不过当年刷的是 `[ok]`、现在会刷 `[error]`。
- **重启后验活**：README 立的门槛是「只认 `curl` 与 `git rev-parse HEAD`」，脚本自己也该量这两样。
  最多 5 次 ×（等 2 秒 + `systemctl is-active` + `curl -fsS -m 5 /visualization`），成功记
  `[ok] restarted, HEAD=…, serving`；失败记 `is-active` 的状态并附 `journalctl -u … -n 5` 尾部。
  探针打 `/visualization` 而不是 API：那是静态路由，不会被冷启动时 `_ensure_demo_data()` 的首次
  重建拖过 5 秒超时（打 API 必然假失败）。

已有的 `flock -n 9`、`timeout 90 git -c http.version=HTTP/1.1 fetch`、sha 解析守卫、
「无新提交就安静退出」四行**一行没动**。

### 7. 手机上文本雨按钮不再抢页签的点击：计划里的修法是错的

计划里写的是「≤560px 给按钮加 `z-index: 20`，压到页签条的 `z-index: 30` 之下」。**实测无效**，
原因值得记一笔：`.container` 带 `backdrop-filter`（配上 `position: relative; z-index: 1`），
整个子树在根层叠上下文里只算作 `z-index: 1`——页签条自己的 `z-index: 30` 被关在这个层叠上下文里，
**根本出不去**。按钮不管是 20 还是 9999，只要压在页签上就永远赢。改 z-index 是死路。

真正的修法是**几何避让**（`syncMatrixBtnDodge`，`d3-charts.js`）：两者矩形相交时，把按钮抬到页签条
上沿之上 12px；不相交就还原。几个要点：

- 判断只用「页签条的矩形」＋「按钮不躲时**该在**的位置」，**刻意不读按钮当前的矩形**——否则
  抬起后不相交 → 还原 → 又相交 → 再抬起，会自激成抖动。
- 重算的时机：滚动、改窗口、`load`，外加一个盯 `document.body` 的 `ResizeObserver`（页签条上方
  那片一变高变矮就推着页签条在文档里移动）；rAF 合并，一帧里只量一次。
- 两档靠 CSS 变量 `--anchored-bottom` 分开（只有 ≤560px 那条规则给它赋值）。**不能**拿
  `getComputedStyle(btn).top` 判断：对定位元素浏览器返回的是**算好的像素值**（实测返回 `"662px"`
  而不是 `"auto"`），拿它分档会永远走进桌面分支。
- 桌面档（按钮钉在右上角）完全不参与：内联的 `bottom` 必须摘干净——`top` 与 `bottom` 同时有值、
  高度又是 `auto` 时，盒子会被拉伸成从上沿到下沿的长条，而不是保持一颗药丸。
- 那个 `z-index: 20` 保留了，但注释改成「万一将来层叠关系变了」的保险，并写明它治不了当下的病。

### 8. 删掉最后一本书，空目录一并清掉

`delete_library_book` 删完文件后顺手 `rmdir` 一下访客目录。`rmdir` 只在目录为空时成功，

```
